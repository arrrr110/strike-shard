# 回合生命周期 产品需求文档

> 创建日期: 2026-09-30
> 变更名: turn-lifecycle
> 上游设计输入: `design/Roguelike三国弹棋策划案-v6.md`（回合生命周期、得分体系）、`design/Roguelike三国弹棋策划案-v7-关卡.md`（敌方 AI、卡池）

## 需求概述

把《弹棋·三国》的对局从"自由操作的单球原型"升级为**由回合阶段驱动的桌面战棋**：一个回合依次经过阶段机的若干阶段，其中只有「选中角色 + 蓄力激发」和「移动碰撞直到静止」两个阶段承载真实玩法，其余阶段本期以 pass 占位；阶段机同时是棋盘物理静止判定、ZOC 围攻结算、以及未来敌方 AI 的挂载点。

## 核心功能

### 功能 1：回合阶段状态机

**描述**：回合生命周期建模为一条状态序列，每个阶段只回答三个问题——进入时做什么、什么时候算完成、退出时做什么。阶段机的推进由"完成条件"轮询驱动（每物理帧检查一次，至多推进一个阶段），而不是信号链或协程。

**阶段序列**（本期共 9 个）：

| 阶段 | 中文名 | 本期状态 | 完成条件 |
| --- | --- | --- | --- |
| `TURN_START` | 回合开始 | pass | 恒真 |
| `ACTION` | 行动枢纽（配置卡片 / 点选棋子 / 结束回合） | 实现 | 点中一枚己方棋子，或点了"结束回合" |
| `SELECT` | 选中角色 | 实现 | 左键按下 |
| `CHARGE` | 蓄力激发 | 实现 | 左键松开 |
| `MOTION` | 角色移动/碰撞（直到静止） | 实现 | 棋盘上所有棋子静止 |
| `HIT_SETTLE` | 发起攻击 / 释放技能 | pass | 恒真 |
| `ZOC_SETTLE` | 检测 ZOC / 结算分数 | pass | 恒真 |
| `TURN_END` | 回合结束 | pass | 恒真 |
| `ENEMY_TURN` | 敌方回合 | pass | 恒真 |

**关键边界**：

- 「配置卡片技能」**不是阶段**：它必须能与「选中角色/蓄力激发」交替进行（v6 第 3 节明确"步骤 1-3 可交替操作，非严格顺序"）。因此它是 `ACTION` / `SELECT` / `CHARGE` 阶段内随时可用的**动作**，而不是一个必须先走完的状态。
- pass 阶段不是"空实现"，而是"完成条件恒真的阶段"：它照样经历 enter/exit 并发出阶段变更信号，未来填充内容时不需要改动阶段机本身。
- 每物理帧至多推进一个阶段（用 `if` 而非 `while` 驱动推进），避免多个 pass 阶段在同一帧内互相循环造成死循环；代价是连续穿过 7 个 pass 阶段约需 0.12 秒，肉眼不可见。

### 功能 2：选中角色与蓄力激发

**描述**：玩家的开火手势拆成两段，对应"先点选、再蓄力"。

1. **点选**（`ACTION` → `SELECT`）：在棋盘内点击一枚己方棋子 → 该棋子进入选中态（视觉高亮）并开始显示瞄准线，瞄准线方向跟随鼠标。
2. **蓄力**（`SELECT` → `CHARGE`）：按住左键 → 蓄力值按固定速率增长，蓄力条随蓄力值伸长。
3. **激发**（`CHARGE` → `MOTION`）：松开左键 → 沿"棋子 → 鼠标"方向施加与蓄力值成正比的冲量。

**边界条件**：

- 正常情况：点选 → 按住 → 松开，三段连续完成，进入 `MOTION`。
- 未选中棋子时按住左键：不进入 `CHARGE`，不蓄力。
- 选中后改选：点击另一枚己方棋子 → 重新进入 `SELECT`，选中态转移（本期只有一枚可操作棋子，多棋子后才实际生效）。
- 选中后取消：点击棋盘内空白处或按 Esc → 回到 `ACTION`，清除选中态与瞄准线。
- **每回合只能发射一枚棋子**（见「功能 3」的边界）；其余己方棋子本期不可被选中，只能被碰撞推动。
- **松开左键是唯一不可撤销点**：一旦松开，冲量施加、蓄力清零，本回合不可重来（对应 v6"确认后不可撤销"）。

### 功能 3：移动碰撞（直到全场静止）

**描述**：冲量施加后物理引擎接管，棋子互相碰撞、撞墙反弹、受恒定滚动阻力减速，直到**棋盘上所有棋子**静止，本阶段结束。

**边界条件**：

- 静止判定是**棋盘级**的，不是棋子级：一发球打出去后，被撞的敌方棋子会继续运动并可能撞到第三枚棋子，必须等到全场（含己方队友）静止才算本次行动结束。
- **静止判定必须去抖**：连续 N 个物理帧（约 0.1 秒）所有棋子的线速度与角速度都低于阈值，才判定为静止。碰撞瞬间速度可能恰好过零，单帧判定会误判。
- **必须有超时兜底**：卡在边缘、反复微弹的棋子可能长时间无法满足静止条件，超时后强制结束本阶段并输出一条警告日志（该日志本身是物理参数的排查线索）。
- 碰撞发生在本阶段内，**碰撞伤害是双向的**（碰撞双方都受伤），且**即时结算**，不等回合末。
- 己方其他棋子被撞动是合法且预期的行为（v6 §1.5"队友当弹板"）。

### 功能 4：ZOC 围攻检测与结算

**描述**：全场静止后，在 `ZOC_SETTLE` 阶段做一次**本方全体 ZOC 检测**：若某敌方棋子 X 同时落在行动棋子的 ZOC 与至少一个其他己方棋子的 ZOC 内，则判定为**围攻**，所有罩住 X 的本方角色一起对 X 发起攻击，形成本回合的第二次伤害结算。

**边界条件**：

- 判定基于**全场静止后的终局站位**，不是移动过程中的实时位置。
- ZOC 覆盖关系是一个**纯查询**（"某棋子被哪些本方棋子罩住"），任何需要它的地方（结算、未来 AI 推演、UI 高亮）都实时计算，不缓存、不设状态，避免"忘记更新"。
- 未形成围攻（只有 1 个本方 ZOC 覆盖）时的行为 `[待确认]`。
- 围攻伤害的方向（单向 / 双向）与具体数值公式 `[待确认]`。

## 用户场景

### 场景 1：一个完整的玩家回合

**入口**：Godot 编辑器运行 `sences/main.tscn`（主场景）。
**触发条件**：游戏开始，处于玩家回合的 `ACTION` 阶段。
**操作流程**：

1. 玩家点击棋盘内自己的一枚棋子 → 棋子高亮，瞄准线跟随鼠标。
2. 玩家按住左键 → 蓄力条开始增长，瞄准线按蓄力比例缩短。
3. 玩家松开左键 → 棋子沿瞄准方向飞出，蓄力条清零，进入 `MOTION`。
4. 棋子撞上敌方棋子 → 双方各自受到碰撞伤害（即时结算）。
5. 棋子减速停住，被撞的敌方棋子也停住 → 全场静止，进入 `ZOC_SETTLE`。
6. 若该敌方棋子同时落在另一枚己方棋子的 ZOC 内 → 触发围攻，相关本方角色一起攻击它。
7. 阶段机继续走完 `TURN_END` → `ENEMY_TURN`（本期 pass）→ 回到 `TURN_START`。

### 场景 2：选中后反悔

**入口**：同场景 1 的步骤 1 之后。
**触发条件**：已选中一枚棋子，但尚未按住左键。
**操作流程**：

1. 玩家点击棋盘内空白处（或按 Esc）→ 选中态清除，瞄准线消失，回到 `ACTION`。
2. 玩家可以重新点选任意一枚己方棋子。

### 场景 3：本回合不发射

**入口**：`ACTION` 阶段。
**触发条件**：玩家不想在本回合发射任何棋子。
**操作流程**：

1. 玩家点击"结束回合"按钮 → 直接跳到 `TURN_END`，跳过本次发射。
2. `[待确认]` "结束回合"按钮的触发方式与位置（本期是否做 UI 按钮）。

## 边界条件

| 场景 | 处理方式 |
| --- | --- |
| 左键在棋盘矩形外按下 | 不进入 `CHARGE`，不蓄力（沿用现有 `table_rect` 判定） |
| 未选中棋子就按住左键 | 不进入 `CHARGE`，不蓄力 |
| 蓄力过程中鼠标移出棋盘 | 保持上一次的瞄准方向继续蓄力（沿用现有行为），不中断 |
| 全场长时间无法静止 | 超时强制结束 `MOTION`，并输出警告日志 |
| 一发球把己方队友撞动 | 合法行为；队友的 ZOC 参与围攻判定 |
| 敌方回合 / 结算阶段玩家点击鼠标 | 棋子不接受输入（由阶段机发放操作许可，棋子不自行判断） |
| 已发射过的棋子在本回合再次被点击 | 不可选中（本期每回合仅一枚，由 `ACTION`/`SELECT` 的操作许可拦截） |
| `MOTION` 阶段中所有棋子速度为 0 但角速度不为 0（原地打转） | 视为未静止，继续等待（角速度有独立阈值） |

## 非功能需求

- **性能**：静止判定每物理帧遍历全部棋子（单场 ≤ 10 枚），不得在遍历中分配新数组，避免每帧 GC 抖动。
- **手感**：静止判定的去抖窗口 ≤ 0.1 秒，即最后一名棋子停稳后 0.1 秒内进入下一阶段。
- **运行环境**：Godot 4.7 + `gl_compatibility` 渲染后端（本机 MoltenVK 无法创建 Forward+/Mobile 计算管线），物理为 2D 物理。
- **离线自包含**：全部实现与验证仅依赖本地项目目录，不引入任何外部服务或内部平台依赖。

## 验收标准

| 核心功能 | 验收标准 |
| --- | --- |
| 功能 1：阶段状态机 | 运行主场景 → 控制台能观察到阶段按 `TURN_START → ACTION → … → ENEMY_TURN → TURN_START` 循环推进；未实现的阶段在单帧内自动穿过，不需人工干预 |
| 功能 2：选中与蓄力 | 点击己方棋子 → 棋子高亮且出现瞄准线；按住左键 → 蓄力条增长；松开 → 棋子飞出且蓄力条清零 |
| 功能 2：取消选中 | 选中后点空白处或按 Esc → 高亮与瞄准线消失，可重新点选 |
| 功能 3：全场静止 | 发射后撞动第二、第三枚棋子 → 阶段机等到**所有**棋子停稳后才进入 `ZOC_SETTLE`，而非发射的那一枚停稳就进入 |
| 功能 3：去抖 | 棋子碰撞的瞬间（速度过零）不触发阶段推进 |
| 功能 4：围攻 | 构造"行动棋子的 ZOC 罩住敌方 X，且 X 还被另一枚己方棋子罩住"的站位 → 两个本方角色都攻击 X |
| 功能 4：ZOC 查询 | 移动任意己方棋子改变覆盖关系后，重新查询立即返回新结果（无缓存残留） |

## 非目标（本期不做）

- **配置卡片技能**：不实现打牌、势、费用、手牌 — `ACTION` 阶段只保留点选与结束回合。
- **发起攻击 / 释放技能**：武将被动（关羽温酒、赵云白马银枪、周瑜抚琴）与专属卡效果不实现。
- **结算分数与血条**：伤害数值、HP 扣减、得分曲线不实现（本期只产出"谁被谁围攻"的判定结果）。
- **回合结束的收尾逻辑**：弃手牌、专属卡洗回牌库、抽牌、疲劳伤害不实现。
- **敌方回合 AI**：v7 §2.2 的行为树不实现，`ENEMY_TURN` 保持 pass。
- **多棋子操控**：不实现"一回合发射多枚"，也不实现"选中任意己方棋子"的完整多棋子 UI 态。
- **棋盘边缘类型区分**：荆棘边、深渊区域不实现，四边均为统一弹性边。

## 待确认事项

以下条目在本次讨论中未拍板，进入 specs / design 阶段前需要确认：

1. **围攻的必要条件**：行动棋子是否**必须**参与围攻？（当前假设：必须。否则静止不动的棋子也能白拿围攻收益，与"主动出击"的张力冲突）
2. **围攻伤害方向**：单向（只有被围的敌方 X 受伤）还是双向（X 反击每个围攻者）？这是唯一会明显改变手感的一条 —— 单向让"合围"收益极高，双向让"贴脸合围"有代价。
3. **围攻伤害公式**：是每个围攻者各打一次基础攻击力（4），还是沿用 v6 的 8 / 24 / 48 曲线？
4. **只有 1 个 ZOC 覆盖时**（未形成围攻）的行为：无效果，还是有单独的"单域"结算？
5. **"每回合只能发射一枚"与卡池的冲突**：v6 有「额外射击：本回合可额外击打 1 枚棋子」、v7 有「冲锋号角：本回合可额外击打 2 枚棋子」。若"每回合一枚"是硬规则，这两张卡需要删改；若是基础规则（卡牌可突破），阶段机需保留 `shots_left` 循环开关。
6. **"结束回合"的触发方式**：本期是否提供 UI 按钮，还是先用键盘快捷键占位？
7. **物理量纲**：v6 的 `ZOC 半径 2.0`、`质量 2.0`、`摩擦 0.4`、`e=0.3` 均为无单位抽象值。落到 Godot 需换算为像素与物理量（建议 ZOC 半径以"球半径 × N"定义）；另注意 `e` 与 Godot `bounce` 语义相反，需按 `bounce = 1 - e` 映射。

## 回滚计划

- **改动性质**：纯新增脚本（`game_flow.gd` / `board.gd` / `turn_context.gd`）+ `player.gd` 演进 + `main.tscn` 节点调整，无数据迁移、无存档格式变化、无外部依赖引入。
- **回滚方式**：`git revert` 对应的实现提交即可；演进前的 `player.gd` 完整版本在 git 历史 `94e546f`（修复pipline）中可随时取回。
- **部分回滚**：若"先点选、再蓄力"两段式手感在编辑器验证中不通过，可单独把 `SELECT` + `CHARGE` 合并回单段式（按下即选中并蓄力），阶段机骨架与其余阶段不受影响。
- **回滚验证**：回滚后运行主场景，应回到"单球自由蓄力发射"的当前行为，且调试 Label 正常刷新。
