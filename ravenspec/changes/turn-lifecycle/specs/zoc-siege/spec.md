## ADDED Requirements

### Requirement: ZOC 覆盖查询是纯查询

系统 MUST 以纯查询的方式提供"某棋子被哪些本方棋子控制域覆盖"的结果：查询必须基于棋子的当前坐标实时计算，不得缓存覆盖关系，也不得将覆盖关系保存为棋子状态。

#### Scenario: 移动后查询立即反映新结果

- **WHEN** 一枚己方棋子被碰撞推动到新位置，改变了它对某个敌方棋子的覆盖关系
- **THEN** 下一次查询立即返回更新后的覆盖集合，不出现旧结果的残留

#### Scenario: 同一查询被多处复用

- **WHEN** 同一物理帧内，围攻结算与 UI 高亮都需要某个敌方棋子的覆盖集合
- **THEN** 两者调用同一个查询入口，得到一致的结果

#### Scenario: 查询不修改任何状态

- **WHEN** 任意时刻调用覆盖查询
- **THEN** 查询过程不改变棋子位置、速度或任何阶段机状态

### Requirement: 围攻判定

当且仅当某个敌方棋子 X 同时满足以下两个条件时，系统 MUST 判定 X 处于围攻状态：(1) 本回合被发射的行动棋子在其控制域内覆盖 X；(2) X 还被至少一枚其他己方棋子的控制域覆盖。

#### Scenario: 行动棋子加一名队友形成围攻

- **WHEN** 行动棋子的控制域覆盖敌方棋子 X，且 X 同时被另一枚己方棋子的控制域覆盖
- **THEN** 判定 X 处于围攻状态，覆盖 X 的两枚本方棋子都参与攻击 X

#### Scenario: 行动棋子加两名队友形成围攻

- **WHEN** 行动棋子与另外两枚己方棋子的控制域同时覆盖敌方棋子 X
- **THEN** 判定 X 处于围攻状态，覆盖 X 的三枚本方棋子都参与攻击 X

#### Scenario: 行动棋子未覆盖则不构成围攻

- **WHEN** 敌方棋子 X 被两枚己方棋子覆盖，但这枚两棋子都不是本回合被发射的行动棋子
- **THEN** 不判定为围攻，X 按未成围攻的规则结算

#### Scenario: 只有行动棋子一人覆盖则不构成围攻

- **WHEN** 只有行动棋子一人的控制域覆盖敌方棋子 X，没有任何其他己方棋子覆盖 X
- **THEN** 不判定为围攻，X 按未成围攻的规则结算

### Requirement: 围攻为单向伤害

围攻成立时，伤害 MUST 是单向的：只有被围攻的敌方棋子受到伤害，参与围攻的本方棋子不受到任何伤害。

#### Scenario: 围攻只伤被围方

- **WHEN** 敌方棋子 X 被两枚本方棋子围攻并完成结算
- **THEN** X 受到伤害，参与围攻的两枚本方棋子均不掉血

#### Scenario: 围攻参与数越多伤害越高

- **WHEN** 同一个敌方棋子分别处于 2 个和 3 个本方控制域的覆盖下
- **THEN** 3 个覆盖时的结算伤害不低于 2 个覆盖时的结算伤害

### Requirement: 未成围攻时为双向伤害交换

未构成围攻时（只有一枚本方棋子覆盖敌方棋子 X），系统 MUST 在 X 与该覆盖方棋子之间进行双向伤害结算：双方都受到伤害。

#### Scenario: 单域覆盖双向掉血

- **WHEN** 只有行动棋子一人的控制域覆盖敌方棋子 X
- **THEN** X 与该行动棋子都受到伤害

#### Scenario: 双向交换的双方各自独立计算

- **WHEN** 未成围攻的双向结算发生
- **THEN** 双方受到的伤害各自按其自身的攻击力与修正计算，不使用同一个数值

### Requirement: 结算基准为静止后的终局站位

`ZOC_SETTLE` 阶段的围攻判定 MUST 基于棋盘上所有棋子静止之后的终局坐标，不得使用移动过程中的实时坐标。

#### Scenario: 运动途中经过不算数

- **WHEN** 行动棋子在飞行途中曾经短暂覆盖某个敌方棋子，但停稳后不再覆盖它
- **THEN** 该敌方棋子不被判定为围攻

#### Scenario: 停稳后才结算

- **WHEN** 阶段机仍处于 `MOTION` 阶段，棋子尚未全部停稳
- **THEN** 不进行任何围攻判定

### Requirement: ZOC 半径是可调参数

ZOC 半径 MUST 以可在 Godot 编辑器中直接调整的导出参数形式提供，单位为像素；半径变化后覆盖查询与围攻判定必须立即按新半径生效，无需改动代码。

#### Scenario: 在编辑器中调整半径

- **WHEN** 用户在编辑器中把 ZOC 半径导出参数改为另一个像素值并重新运行
- **THEN** 覆盖查询按新的半径判定，围攻的触发范围随之改变

#### Scenario: 半径对所有棋子一致

- **WHEN** 同一枚敌方棋子分别接受两枚不同己方棋子的覆盖查询
- **THEN** 两次查询使用同一个半径值，不因棋子不同而不同

### Requirement: 伤害数值可配置且本期不定义

围攻与普通伤害交换的数值 MUST 以可调导出参数的形式占位，本期不定义具体数值；数值的确定不得要求改动围攻判定逻辑。

#### Scenario: 数值参数占位

- **WHEN** 本期实现完成时查看棋子的导出参数
- **THEN** 存在用于围攻伤害与普通交换伤害的可调参数，其默认值可以是占位值

#### Scenario: 改数值不改判定

- **WHEN** 用户调整伤害数值参数
- **THEN** 围攻与未成围攻的判定结果不变，只有结算出的伤害量变化
