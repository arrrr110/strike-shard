## ADDED Requirements

### Requirement: 全场静止判定

`MOTION` 阶段的完成条件 MUST 基于**棋盘上所有棋子**的运动状态，而不是仅基于本回合被发射的那一枚棋子；只要还有任意一枚棋子处于运动状态，本阶段就不得结束。

#### Scenario: 只有行动棋子停下不算静止

- **WHEN** 被发射的棋子已经停稳，但被它撞到的另一枚棋子仍在运动
- **THEN** `MOTION` 阶段不结束，阶段机继续等待

#### Scenario: 连锁碰撞后全部停稳

- **WHEN** 一发棋子连续撞动两枚其他棋子，随后三枚棋子全部速度降到阈值以下
- **THEN** `MOTION` 阶段结束，阶段机推进到 `HIT_SETTLE`

#### Scenario: 己方队友被撞动同样计入

- **WHEN** 被发射的棋子撞动了一枚己方队友，队友仍在运动
- **THEN** `MOTION` 阶段不结束，直到该队友也停稳

### Requirement: 静止判定去抖

静止判定 MUST 采用连续多帧确认：只有当所有棋子在连续 N 个物理帧内都低于速度阈值时，才判定为静止；单帧速度过零不得触发静止。

#### Scenario: 碰撞瞬间速度过零不触发

- **WHEN** 两枚棋子相撞，其中一枚的线速度在碰撞的瞬间恰好接近 0，但下一物理帧又被弹开
- **THEN** 不判定为静止，`MOTION` 阶段继续

#### Scenario: 连续静止帧数达到阈值才结束

- **WHEN** 所有棋子的速度连续低于阈值达到约定的帧数
- **THEN** 判定为静止，`MOTION` 阶段结束

#### Scenario: 中途有棋子重新运动则重新计数

- **WHEN** 静止帧计数尚未达到阈值时，任意一枚棋子的速度重新超过阈值
- **THEN** 静止帧计数归零，重新开始累计

### Requirement: 角速度独立阈值

静止判定 MUST 同时检查线速度与角速度，且两者使用各自独立的阈值；原地打转（线速度接近 0 但角速度显著）不得判定为静止。

#### Scenario: 原地打转不算静止

- **WHEN** 一枚棋子的线速度低于阈值，但角速度高于角速度阈值
- **THEN** 不判定为静止，`MOTION` 阶段继续

#### Scenario: 线速度与角速度均低于阈值

- **WHEN** 所有棋子的线速度与角速度都分别低于各自的阈值，并持续达到约定的帧数
- **THEN** 判定为静止

### Requirement: 静止判定超时兜底

静止判定 MUST 具备超时兜底：当等待时间超过约定上限时，强制结束 `MOTION` 阶段，并输出一条可供排查的警告日志。

#### Scenario: 超时强制结束

- **WHEN** 存在棋子因反复微弹或卡在边缘而长时间无法满足静止条件，等待时间超过上限
- **THEN** `MOTION` 阶段被强制结束，阶段机继续推进到 `HIT_SETTLE`

#### Scenario: 超时输出警告日志

- **WHEN** 静止判定因超时而被强制结束
- **THEN** 输出一条警告日志，内容包含触发超时的棋子及其速度，供排查物理参数

#### Scenario: 正常静止不产生警告

- **WHEN** 所有棋子在超时上限之内正常停稳
- **THEN** 不输出任何超时警告日志

### Requirement: 静止判定不产生每帧内存分配

静止判定的每物理帧执行 MUST NOT 分配新的容器对象，以避免持续的垃圾回收抖动。

#### Scenario: 多棋子场景下的稳定帧

- **WHEN** 棋盘上有 10 枚棋子，`MOTION` 阶段持续数百个物理帧
- **THEN** 静止判定的遍历过程不创建新的数组或字典对象

#### Scenario: 棋盘级查询复用同一遍历

- **WHEN** 同一物理帧内既有静止判定、又有其他需要遍历棋子的查询
- **THEN** 两者共用棋子的存储结构，不各自构造一份临时列表
