## 定位与边界

技能是**独立的内容模块**：不写在角色脚本里，也不是场景树上的子节点。
角色、召唤物、归属方或对局只负责**拥有**技能；一个中央 `SkillRuntime` 负责
在正确的时刻**调用**它。技能只产出事件与修正，不直接改血量、速度或 UI。

三条边界：

1. **不做通用技能 DSL**。技能实现仍然是 GDScript 类；本文的「定义模板」是写技能时的
   必填清单，不是配置语言。
2. **核心不认识具体技能**。核心只认识触发点、事件和效果契约；技能 id、名字、
   动画键都在内容层。
3. **技能之间不互相调用**。它们通过同一条事件链与结算顺序交互，避免递归。

> 2026-11-02 讨论结论：组件化落在**运行时零件**上（宿主 / 触发 / 条件 / 效果 /
> 生命期 / 作用域），不是先做一张配置表。等同类技能重复到值得时，再把「拼装」
> 提升为 Resource 字段——那是由内容量逼出来的，不是现在预设的。

## 一、五个维度 + 宿主

| 维度 | 回答的问题 | 取值 |
| --- | --- | --- |
| 宿主 | 技能属于谁 | 角色 / 召唤物 / 归属方 / 对局 |
| 触发 | 什么时候轮到它 | 碰撞 / 伤害意图 / 对局开始 / 回合开始 / 回合结束 / 手动激活 |
| 条件 | 这次该不该它起作用 | 敌我、单次/常驻、回合范围、层数、是否失能 |
| 效果 | 改什么 | 属性、血量、伤害修正、速度、位置、预约 |
| 生命期 | 多久、几次 | 即时 / 常驻 / 单次 / 预约 / 累积 |
| 作用域 | 对谁 | 自己 / 我方 / 敌方 / 全体 / 随机 |

宿主是正交维度：角色有位置、血量、控制域；归属方只有血量池与对局级状态；
对局没有任何位置。不要造一个「什么都有、一半字段是 null」的万能宿主接口。

## 二、技能定义模板（必填）

每个技能在内容层必须写全下面这些字段。**机制字段与演出字段分开**：
核心只读机制，表现层只读演出键。

| 字段 | 含义 | 例（#2 碰撞后停止） |
| --- | --- | --- |
| 描述 `des` | 玩家可读的一句话 | 碰撞到首个敌方角色后，本角色速度归零 |
| 宿主 | 角色 / 召唤物 / 归属方 / 对局 | 角色 |
| 触发事件 | 碰撞 / 伤害意图 / 对局开始 / 回合开始 / 回合结束 / 手动激活 | 碰撞 |
| 条件 | 敌我、单次/常驻、回合范围、层数、是否失能 | 单次起效、敌方角色、本回合有效 |
| 目标 | 自己 / 我方 / 敌方 / 全体 / 随机 | 自己 |
| 效果事件 | 速度归零 / 伤害修正 / 免疫 / 治疗 / 位置重排 | 棋子速度归零 |
| 演出 | animation-x / 特效 / 日志键 | animation-x |
| 状态 | 待激活 / 已激活 / 已失效 | 待激活 → 已激活 → 已失效 |

### 状态机

```
待激活 --条件成立--> 已激活 --结算完成--> 已失效（一次性 / 消耗型）
   ^                    |
   +----常驻被动--------+（结算后回到待激活）

已激活 --宿主失能 / 被元规则取消--> 已失效（取消）
```

- **待激活**：已挂载，等条件。
- **已激活**：条件成立，目标锁定、修正已登记；等待碰撞或结算。
- **已失效**：已消耗、已过期、被取消，或宿主失能。

## 三、规则层级（元规则优先）

| 层 | 规则 | 冲突时 |
| --- | --- | --- |
| L0 元规则 | 棋子不可重叠；生命值为 0 = 失能；碰撞必产生伤害结算机会；造成失能的那一下超出部分丢弃，**对失能角色的伤害转化为攻击方归属方的头像攻击力，回合末双方各自结算** | **技能不得违反**；违反即设计错误 |
| L1 核心规则 | 回合、每回合一次发射、双向碰撞伤害、ZOC 单向伤害 | 技能不得改变，除非显式写死 |
| L2 技能 | 条件、效果、生命期、作用域 | 按本文的激活/结算顺序处理 |
| L3 表现/日志 | 只读事件 | 不得反向影响 L0–L2 |

**「碰撞必产生伤害结算机会」不等于「伤害必生效」**：碰撞总是生成一次伤害结算，
技能可以按条件修正或免疫它；不能因为 #2 让棋子停下就跳过伤害。

## 四、失能状态与技能

2026-11-02 修订：角色血量归零不再叫「薄弱点全功能可用」，改为**失能**（旧称仍可检索）。

| 能力 | 失能后 |
| --- | --- |
| 物理实体 / 被撞 | 保留 |
| 挂载技能（主动 + 被动） | **全部关闭** |
| ZOC 覆盖（作为提供者） | **关闭**（算被动能力） |
| 被碰撞 / 被围攻（作为目标） | **保留**：仍可被敌方碰撞，仍可作为 ZOC 围攻目标 |
| 可被选中 / 发射 | **保留**（玩家动作，不是角色能力） |
| 受到伤害 | 角色血量已为 0；**当场不扣归属方血**，伤害计入**攻击方归属方**的**一次性头像攻击力**，回合末双方各自结算 |
| 治疗 / 复活 | 当前不可；未来有**代价较大的全局复活技能**（设计储备） |

- 失能不是退场：角色仍在棋盘上，仍然可以作为物理体被撞、被发射、被围攻。
- **失能阻止新的激活，并取消未结算的已激活效果**；已经应用在碰撞上的伤害修正不回滚。
- 「失去的结算条件不注销」只适用于普通条件变化（目标移动、层数变化、血量变化），
  **不适用于宿主失能**——失能是元规则，优先。
- 保护低血角色的动机从「防止伤害转嫁」变成「防止能力全关 + 阻止敌人积累头像攻击力」。

### 归属方攻击力（失能伤害转化，2026-11-02 定）

> **攻击力只是结算形式/表演**：规则结果等价于双方归属方血量按对方本回合造成的
> 失能伤害互相扣减。它不是可消费资源，不能拿来做别的用途，也不改变角色 `atk`。

1. **造成失能的那一下**：超出剩余血量的部分仍然**丢弃**——只有角色已经失能后受到的伤害才转化。
2. **失能期间**：敌方向它造成的碰撞/ZOC/技能伤害**当场不扣归属方血**，而是计入
   **攻击方归属方**的**一次性头像攻击力**（`owner_attack_power[attacker_owner_id]`）。
   - 攻击力是 **owner 级**：同一归属方多个失能角色、多次攻击的伤害汇总到同一个头像。
   - 只有「敌方」对「已失能角色」的伤害计入；友方伤害、以及造成失能那一下的超出部分不计入。
3. **每次 `TURN_END` 的最后**（回合结束技能之后）：双方各自把头像攻击力打到**对方归属方**
   血量上（**各打各的**，不做差值/抵消）。双方结算后攻击力清零；**双方都结算完再检查胜负**。
   - 例：我方 10、敌方 4 → 敌方归属方 -10，我方归属方 -4。
   - 例：我方 10、敌方 0 → 敌方归属方 -10，我方不变。
4. **归属方血量归零 → 该方失败，对局结束**。**双方同一回合末同时归零 → 平局**。
5. 失能角色**不提供 ZOC 覆盖**，但**可以被碰撞、可以被围攻**；对这些攻击的伤害照常
   转化为攻击方归属方的攻击力。
6. 攻击力属于攻击方归属方，不因目标被治疗/复活而回滚（复活是未来设计）；`reset_match` 清零。
7. 演出是 **owner 级**：双方头像像炉石武器攻击一样，把自己的攻击力打向对方；
   不是棋子级演出。

> **失能是赛点，不是胜负条件**：棋盘上的角色失能不等于输；只有归属方血量归零才分胜负。
> 失能给对手提供积累结算值的途径，所以它是「赛点」——逼近胜负，但不直接判负。

## 五、碰撞时的技能结算顺序

2026-11-02 定。一次**伤害碰撞**（行动角色 × 敌方）按以下顺序：

1. **去重**：同一物理步、同一对棋子只产生一个碰撞事实。
2. **主动方激活**：本回合归属方的所有符合条件技能，按
   `priority → card_index → mount_seq` 激活。
   **激活 = 锁定目标 + 登记本次碰撞的修正**（伤害上限、免疫、碰撞后位移等），
   不是立刻改世界。
3. **被动方激活**：对手方同理；已失能的宿主不参与。
4. **碰撞**：双方按元规则交换血量；应用已登记的修正。**若目标是已失能角色，伤害计入
   攻击方归属方的头像攻击力**（见第四节），不当场扣归属方血。
5. **结算**：所有已激活技能结算剩余效果；失能宿主的未结算效果取消；发出日志/表现事件。

为什么把「执行」拆成「激活」和「结算」：只有这样才能同时满足 #2 与 #5——
#5 的免疫必须在碰撞前登记，#2 的停止必须在碰撞后落地。直接「执行完整效果」会让
其中一个失效。

### 顺序细则

- **主动方 = 本回合归属方**（`GameFlow.active_owner_id()`），不是「谁先发起技能」。
  本回合中我方所有角色的技能（包括没被发射的角色）都优先于对方。
- 同阵营内按 `priority → card_index → mount_seq` 排序，不依赖注册先后。
- **普通条件丢失不回溯取消**：被动方的技能在主动方结算后失去条件，仍然结算。
- **目标失效**：跳过该目标，但效果不取消、消耗照付。
- **失能是例外**：宿主失能时，未结算效果立即取消。
- **基础碰撞伤害是元规则**：双方同时交换，不因主动方先激活而吞掉被动方的基础伤害。
  对失能角色的那一份不立即扣归属方血，而是转化为攻击方归属方的头像攻击力，
  `TURN_END` 双方各自结算。
- 技能触发技能的环路**暂不专门处理**；实践遇到再加排空上限/触发计数。

## 六、周期模型

模仿炉石传说，只使用三个正式时刻，不发明「大轮」：

| 时刻 | 含义 |
| --- | --- |
| `MATCH_START` | 对局开始，第一回合之前 |
| `TURN_START(owner)` | 某一方的回合开始 |
| `TURN_END(owner)` | 某一方的回合结束 |

延迟技能用「下一次满足条件的 `TURN_START` / `TURN_END`」表达，不用真实时间：

- 「下个我方回合开始时」= 下一次 `TURN_START(owner = 我方)`
- 「下个敌方回合开始时」= 下一次 `TURN_START(owner = 敌方)`
- 「下个回合开始时」= 下一次 `TURN_START(任意)`（必须显式写「任意」）
- 「本回合结束时」= 当前 `TURN_END(active_owner)`

`TURN_START` / `TURN_END` 内仍按「主动方先、被动方后」结算。
每次 `TURN_END(owner)`：先结算回合结束技能（主动方先、被动方后），**最后**双方各自把
头像攻击力打到对方归属方血量上（各打各的，不抵消），随后清零；双方都结算完再检查胜负。
若有人归零，对局结束；**双方同时归零 = 平局**。

当前 `GameFlow` 还没有 `MATCH_START`、回合计数，**敌方回合也没有独立的 `TURN_END`**
（直接回 `TURN_START`），这三项都是【未实现】——归属方攻击力的「每回合末」需要先补上
敌方回合结束钩子。

### #1 立即增益

| 字段 | 内容 |
| --- | --- |
| `des` | 立即为我方一名角色增加攻击力或生命值。 |
| 宿主 | 角色 / 召唤物（目标） |

### #2 碰撞后停止

| 字段 | 内容 |
| --- | --- |
| `des` | 碰撞到首个敌方角色后，本角色速度归零。 |
| 宿主 | 角色 |
| 触发 | 碰撞（与敌方棋子的伤害碰撞） |
| 条件 | 单次起效、敌方角色、本回合有效、宿主未失能 |
| 目标 | 自己 |
| 效果 | 碰撞结算后速度归零 |
| 演出 | animation-x |
| 状态 | 待激活 → 已激活 → 已失效 |

元规则：碰撞伤害照常结算；若碰撞使宿主失能，停止效果取消（失能取消未结算效果）。
物理上只能做到「碰撞响应结束后不再滑行」，不追求贴住接触点——引擎回调拿到的是
已反弹状态，冻结还要再等 3 个物理步。

### #3 受击只掉 1

| 字段 | 内容 |
| --- | --- |
| `des` | 受到碰撞伤害时，本次伤害降为 1 点。 |
| 宿主 | 角色 |
| 触发 | 伤害意图（碰撞） |
| 条件 | 常驻被动、自己是受击方、`hp > 0`、未失能 |
| 目标 | 自己 |
| 效果 | 本次碰撞对自身造成的**总伤害**钳为 1；不溢出；对方仍按元规则承受自己打出的伤害 |
| 演出 | 护盾 / 减伤 |
| 状态 | 待激活 → 已激活 → 回到待激活（常驻）；失能 → 已失效 |

元规则：`hp == 0` 时元规则优先，技能关闭；当前口径只对碰撞伤害生效，不对 ZOC 生效。
失能后受到的伤害计入**攻击方归属方**的头像攻击力（见第四节），#3 不再参与。

### #4 下个我方回合开始治疗

| 字段 | 内容 |
| --- | --- |
| `des` | 下个我方回合开始时，我方全体角色恢复 X 点生命。 |
| 宿主 | 归属方 |
| 触发 | `TURN_START(owner = 我方)` |
| 条件 | 预约一次；到时触发；失能角色不治疗 |
| 目标 | 我方全体角色（`hp > 0`；不含失能；是否含召唤物待定） |
| 效果 | 治疗，钳到 `max_hp` |
| 演出 | 治疗特效 / 数字 |
| 状态 | 待激活 →（预约）→ 已激活 → 已失效 |

周期：下一次 `TURN_START(owner = 我方)`。这是周期模型的**标杆技能**——

### #5 能量护盾

| 字段 | 内容 |
| --- | --- |
| `des` | 每次与敌方棋子碰撞积累 1 层能量；3 层后，下一次与敌方棋子的伤害碰撞免疫伤害，然后层数清零。 |
| 宿主 | 角色 |
| 触发 | 碰撞事实（与敌方棋子）+ 伤害意图 |
| 条件 | 累积、层数 ≥ 3、自己是受击方、未失能 |
| 目标 | 自己 |
| 效果 | 第三层碰撞照常结算；之后护盾待发；下一次与敌方棋子的**伤害碰撞**对自身伤害免疫；免疫后层数清零 |
| 演出 | 充能 / 护盾 |
| 状态 | 待激活（累积）→ 已激活（护盾待发）→ 已失效（免疫后）；失能 → 已失效 |

元规则：只挡自己受到的伤害，不挡自己打出的伤害；墙壁/友方不充能；`hp == 0` 时技能关闭，
之后的伤害计入**攻击方归属方**的头像攻击力（见第四节），#5 不再参与。
免疫必须发 `damage_prevented` 事件，否则日志只能显示 `-0`，看不出是免疫。

### #6 乱斗（全局技能，特殊类）

| 字段 | 内容 |
| --- | --- |
| `des` | 由归属方发起，随机重排所有敌我棋子的位置。 |
| 宿主 | 归属方 / 对局 |
| 触发 | 手动激活 |
| 条件 | 单次、对局中、不可重叠、位置合法 |
| 目标 | 全场棋子（是否含召唤物/失能角色待定；当前按全部物理棋子） |
| 效果 | 冻结物理 → 重排位置 → 恢复；不触发碰撞伤害 |

## 八、游戏日志

技能不写日志文案，只发事件。日志是事件的投影：

| 事件 | 用途 |
| --- | --- |
| `skill_triggered` | 技能条件成立，进入激活 |
| `skill_activated` | 目标锁定、修正登记 |
| `damage_modified` | 伤害被钳制/增加（带 before/after） |
| `damage_prevented` | 伤害被免疫（日志显示「免疫」，不是 `-0`） |
| `skill_settled` | 效果落地 |
| `skill_cancelled` | 宿主失能 / 目标全失效 / 被取消 |
| `skill_expired` | 消耗 / 过期 |
| `owner_attack_power_gained` | 对失能角色的伤害转化为攻击方归属方的头像攻击力（金额、攻击方 owner、来源） |
| `owner_attack_resolved` | `TURN_END` 双方各自把头像攻击力打到对方归属方（我方 X / 敌方 Y、双方 HP 变化） |

日志格式化器由内容层提供名字表，核心不出现具体技能名/卡名。
每个事件带原因链（哪个技能、哪个宿主、哪个碰撞），玩家战报才能解释「为什么只掉 1」。

## 九、与其它模块的接口

- `10-turn`：提供 `TURN_START` / `TURN_END` / `MATCH_START` 与碰撞事实；
  技能模块不自己推进阶段。
- `20-character`：提供宿主属性、失能状态、ZOC 覆盖/目标状态的查询；技能不直接写 `hp`/`atk`。
- `30-card`：卡牌可以授予/挂载/激活技能；卡牌模块不定义技能语义。
- `50-presentation`：消费技能事件；技能不直接播动画。
- **可见性**：**棋盘上的操作、技能触发、头像攻击力、ZOC、角色状态双方都可见；
  只有各自手牌不可见**。技能不做隐藏/迷雾。

## 十二、工程评估与实施顺序

| # | 工程成本 | 主要风险 | 结论 |
| --- | --- | --- | --- |
| 1 | 低 | 永久/临时、失能/复活、`reset_to_home` 清理 | **保留，先做** |
| 2 | 中 | 物理时序：碰撞回调拿到的是已反弹状态，冻结还要再等 3 个物理步 | **保留**，重定义为「碰撞响应结束后归零」，不追求贴住接触点 |
| 3 | 中 | `_apply_damage_to()` 是碰撞/ZOC 共用出口；不区分来源会误钳围攻；钳总伤害还是只钳血量部分；失能后的伤害要转成**攻击方归属方头像攻击力** | **保留**，限定碰撞伤害、钳总伤害、失能关闭 |
| 4 | 高 | 需要周期模型 + 调度器 + `TURN_END` 攻击力结算；治疗/复活；宿主失能后预约是否取消 | **不删，后置**到周期模型之后 |
| 5 | 中高 | 现有碰撞流只为「伤害资格」服务；需要拆出「碰撞事实」层；墙壁/友方是否计数 | **保留**，它是碰撞事实层的强制功能 |
| 6 | 高 | 全盘几何写操作；不可重叠元规则；确定性随机；位置合法性 | **建议删/降级**；第一版只做「随机交换两枚」 |

**实施顺序**：伤害/属性（#1、#3、#5）→ 物理（#2）→ 时间（#4）→ 空间（#6）。
前三个共享同一条伤害意图管线；第二批才碰物理时序；第三批才碰周期模型；
最后才碰全盘几何。不要反过来。

> **归属方攻击力不是技能私有状态**：它是 owner 级的元规则状态，必须和伤害管线一起做，
> 在 `TURN_END` 元规则阶段统一结算。**敌方回合目前没有 `TURN_END`**，实现前要先补钩子。
> 不要把它塞进某个技能实例里。

**删减结论**：

- **#6 是唯一直接与元规则（不可重叠）冲突的场景**，而且它教不会新的技能契约；
  第一版不做全盘乱斗，降级为交换两枚或延后。
- **#4 不删，但必须先有周期模型**，否则它会自己发明一套临时计时，后面所有延迟技能
  都得跟着它走。
- **#3/#5 必须限缩口径**：只对碰撞、只对自己受到的伤害、失能后关闭；否则会误伤 ZOC
  和其他技能。
- **#2 不追求「贴住接触点」**：引擎已经算完反弹，只能覆写速度；定义成「碰撞响应结束后
  不再滑行」才和物理事实一致。
