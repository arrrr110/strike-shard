# 待设计：角色挂载技能

> 状态：**挂起**，需要另外找时间设计机制。本文只记录已定约束与开放问题，不做设计。
> 创建：2026-10-04

## 为什么挂起

用户明确：卡片效果可以赋予**非发射角色**，这类技能**挂载在角色身上**，
有特殊条件会起效或者结束。它是"卡片机制"与"角色机制"的交叉产物，
需要单独一轮设计，不适合塞进当前回合机制的落地范围。

## 已确定的约束

1. **可以赋予非发射角色**。也就是说，技能的存在与"本回合发射了谁"无关——
   没有被弹出的角色同样可能拥有并触发技能。
2. **挂载在角色身上**，不是全局效果、不是玩家身上的效果。技能的宿主是角色实例。
3. **有特殊条件会起效或结束**。存在持续期与结束判定，不是"一次性结算完就没了"。

## 与既有核心的接口（已留位，不需要改动脊梁）

核心已经为它预留了位置，因此**不会阻塞当前回合机制的落地**：

- 技能 = 一组 `EffectRule`，按事件类型注册进 `RuleRegistry`。
- 触发条件 = 规则自己的 `matches(event, ctx)` 判定。
- 起效 / 结束 = 注册与注销规则（或规则内部维护一个状态字段）。
- 宿主绑定 = `Combatant.mounted_skills` 提供技能 id 列表，内容层据此注册规则。

## 开放问题

- **触发时机**：监听哪些事件？（碰撞、伤害、回合阶段切换、其他技能产生的自定义事件）
- **持续期**：以什么为界——回合数、直到某条件成立、还是永久？跨回合怎么存？
- **"结束"的语义**：结束时是否要回滚它造成过的改变（例如临时属性加成）？
- **优先级与嵌套**：技能触发技能时如何避免环？（核心已有"队列串行 + 单次排空事件数上限"的兜底，
  但技能侧是否需要额外的规则，待定）
- **归属与可见性**：敌方技能是否需要在 UI 上可见？"隐藏技能"如何表现？
- **与发射次数规则的关系**：技能能否影响发射（不该影响，但需要明确写死）。
- **数值与平衡**：完全未开始。

## 不阻塞的部分

上表中除"与发射次数规则的关系"外，其余都不影响回合机制的实现。
回合机制落地时只需要保证 `RuleRegistry` 按事件类型注册这一条不变即可。
