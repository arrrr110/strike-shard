# 历史入口：角色挂载技能

> 状态：**已升格**（2026-11-02）。现行设计在 [技能系统](../35-skill/PRD.md) 与
> [技术方案](../35-skill/DESIGN.md)；本文只保留议题的来历，不再维护。
> 创建：2026-10-04 ｜ 迁移：2026-11-02

## 为什么当时挂起

用户明确：卡片效果可以赋予**非发射角色**，这类技能**挂载在角色身上**，
有特殊条件会起效或者结束。它是"卡片机制"与"角色机制"的交叉产物，
需要单独一轮设计，不适合塞进当前回合机制的落地范围。

（2026-11-02 已完成这一轮设计，见文首链接。）

## 已确定的约束（仍然有效）

1. **可以赋予非发射角色**。也就是说，技能的存在与"本回合发射了谁"无关——
   没有被弹出的角色同样可能拥有并触发技能。
2. **挂在宿主上**。2026-11-02 扩展：宿主可以是角色、召唤物、归属方或对局；
   不再只限"角色实例"。
3. **有特殊条件会起效或结束**。存在持续期与结束判定，不是"一次性结算完就没了"。

## 旧接口设想（已被新模块取代）

> 2026-11-02：实际落点是 `SkillRuntime` + `Skill` 契约，不是旧文档写的
> `EffectRule` + `RuleRegistry` 命名；思想保留（按事件/触发点注册、条件匹配、
> 注册与注销的生命周期），但全局技能改走特殊类。

- ~~技能 = 一组 `EffectRule`，按事件类型注册进 `RuleRegistry`。~~
- ~~触发条件 = 规则自己的 `matches(event, ctx)` 判定。~~
- ~~起效 / 结束 = 注册与注销规则（或规则内部维护一个状态字段）。~~
- ~~宿主绑定 = `Combatant.mounted_skills` 提供技能 id 列表，内容层据此注册规则。~~
  → 现在：`mounted_skills` 仍是内容层输入，运行时由 `SkillRuntime` 持有实例与状态。

## 旧开放问题 → 现行答案

| 旧问题 | 现行答案 |
| --- | --- |
| 触发时机 | 碰撞 / 伤害意图 / 回合开始 / 回合结束 / 手动激活；见 [技能系统 PRD](../35-skill/PRD.md) |
| 持续期 | 即时 / 常驻 / 单次 / 预约 / 累积；周期用 `MATCH_START` / `TURN_START(owner)` / `TURN_END(owner)`，不用真实时间 |
| "结束"的语义 | 永久改变直接改基础值；临时改变走修正层，结束移除来源；失能会取消未结算效果 |
| 优先级与嵌套 | 主动方激活 → 被动方激活 → 碰撞 → 结算；同阵营按 `priority → card_index → mount_seq`；死循环**暂不处理** |
| 归属与可见性 | **已定：棋盘上的操作、技能触发、头像攻击力、ZOC、角色状态双方可见；只有各自手牌不可见**。不做隐藏技能/战争迷雾 |
| 与发射次数规则的关系 | **技能不得影响发射边锁**；卡牌模块已写死 |
| 数值与平衡 | **完全未开始** |
