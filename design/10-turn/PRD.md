# 回合机制 产品需求文档

> 模块：`10-turn` ｜ 状态：编写中
> 创建：2026-09-30 ｜ 最近修订：2026-10-10
> 技术方案见 [DESIGN.md](DESIGN.md)

## 需求概述

把《弹棋·三国》的对局升级为**由回合阶段驱动的桌面战棋**：一个回合沿阶段图推进，
玩家在 `PLAYER_TURN` 枢纽上做三件事——装载卡牌、发射（每回合仅一次）、结束回合。

一个回合机制由**三个环节**组成：

| # | 环节 | 内容 |
| --- | --- | --- |
| 1 | **卡牌装载** | 卡牌可以装载到角色上，也可以由玩家直接使用。机制另立模块（见 [卡片机制](../30-card/PRD.md)），本模块只留接口位置 |
| 2 | **选择棋子并蓄能射击** | 点选 → 蓄力 → 激发 → 移动碰撞 → 全场静止。**过程中撞击敌方会插入血量交换** |
| 3 | **ZOC 判断与围攻** | 全场静止后，从**发射棋子的控制域**出发挑一个敌方目标**单向**结算：优先打被本方最多控制域同时罩住的（围攻），没有围攻则打离发射棋子最近的 |

## 核心功能

### 功能 1：回合阶段图【已实现】

**描述**：回合生命周期建模为一张有向图。每个阶段只回答四个问题——进入时做什么、
什么时候算完成、退出时做什么、完成后去哪。推进由"完成条件"轮询驱动（每物理帧检查一次，
**至多推进一条边**），而不是信号链或协程。

**拓扑**（当前实现）：

```
TURN_START ─(停留 1s + 全场静止)→ PLAYER_TURN
PLAYER_TURN ─┬─(发射)→ MOTION ─(全场静止)→ PLAYER_TURN
             └─(结束回合 且 全场静止)→ TURN_END
TURN_END ─(停留 1s)→ ENEMY_TURN ─┬─(bot 发射)→ MOTION ─(全场静止)→ ENEMY_TURN
                                 └─(bot 收工 且 全场静止)→ TURN_START
```

**`MOTION` 返回"谁发起的就回谁那儿"**（靠 `_active_owner` 判定），不写死回 `PLAYER_TURN` ——
这是敌方回合能复用同一套运动/静止/ZOC 机制的前提（2026-10-13）。

**阶段表**：

| # | 阶段 | 中文名 | 完成条件 |
| --- | --- | --- | --- |
| 1 | `TURN_START` | 回合开始 | 停留满 `dwell_sec`（默认 1 秒）**且** 全场静止 |
| 2 | `PLAYER_TURN` | 我的回合 | 出现"发射"→ `MOTION`；或"结束回合"已请求 **且** 全场静止 → `TURN_END` |
| 3 | `MOTION` | 移动碰撞 | 全场静止（去抖确认）；超时兜底 |
| 4 | `TURN_END` | 回合结束 | 停留满 `dwell_sec` |
| 5 | `ENEMY_TURN` | 敌方回合 | 出现"发射"→ `MOTION`；或 bot 已收工 **且** 全场静止 → `TURN_START` |

**关键边界**：

- **为什么是图而不是固定序列**：`PLAYER_TURN` 有三条出边（发射 / 结束回合 / 自环）、
  `MOTION` 有一条回到 `PLAYER_TURN` 的回边。用"固定序列"表达这两件事必须引入特例分支，
  而特例分支就是结构性缺陷的温床。图结构下，每个阶段只声明"我完成后去哪"，不声明特殊分支。
- **每物理帧至多推进一条边**（用 `if` 而非 `while` 驱动）。代价是连续穿过多个阶段
  需要数个物理帧（约 0.1 秒量级），肉眼不可见；收益是彻底排除帧内级联。
- **停留（dwell）不是"空实现"**：`TURN_START` / `TURN_END` / `ENEMY_TURN`
  三个阶段目前只做停留，是为了让玩家看得见回合在推进。以后往里面填内容时，
  不需要改动阶段机本身。
- **选中 / 蓄力 / 射击不是阶段**，是 `PLAYER_TURN` 内随时可用的**动作**，不引起阶段切换。
  与"出牌不是阶段"是同一条道理——凡是必须能与其他动作交替进行的东西，就不该是阶段。
  （2026-10-10 修订：原设计把 `SELECT` / `CHARGE` 列为独立阶段，实测下来那会让
  "选中途中能不能出牌""蓄力途中能不能改选"这类问题必须在阶段机上打补丁。）
- **发射边的锁**：**每一位方各自一把**（索引 = `owner_id`），在自己回合开始时打开，
  发射一次后关闭。这是一个**边上的开关**，不是"剩余次数"计数器——
  结构上不存在"某条路径忘了扣次数"的可能。
  **为什么必须是两把**：玩家出完手走的是 `PLAYER_TURN → TURN_END → ENEMY_TURN`，
  **不经过 `TURN_START`**，一把锁会把敌方锁死（2026-10-13 实测踩到）。
- **静止闸门两个方向都要过**：进 `TURN_END`（进敌方回合）要全场静止，
  进 `PLAYER_TURN`（回我方回合）也要。本期敌方回合不动棋子，所以回程的闸门恒真；
  写成统一条件是给以后真的动敌方棋子留位。

### 功能 2：发射（每回合一次，任意本方角色，可放弃）【已实现】

**描述**：发射是本作的核心机制，类比台球：一个回合只有一次机会，玩家**自选**任意一枚
本方角色弹出。

**交互是"点一下选中、再按一下蓄力"的两次按键**（2026-10-10 修订，原设计是按住不放的三段连续手势）：

1. **点选**：在棋盘内左键点一枚本方角色 → 角色描边高亮，显示瞄准线。**这一下不蓄力。**
2. **蓄力**：在棋盘内任意位置（包括别的角色身上）按下左键 → 蓄力值按 `charge_rate`
   增长，蓄力条随之变长。此时松开即发射。
3. **取消**：右键 → 清除选中态与瞄准线，回到未选中状态。
4. **放弃**：玩家可以不发射任何角色，直接点"结束回合"。这是**合法且必要的战术选择**
   （例如保持站位、等待 ZOC 成形、避免把队友撞散）。

**边界条件**：

- 发射前，本方**任意**角色均可被选中；发射后，本方所有角色本回合均不可再被选中，只能被碰撞推动。
- **未选中角色时按左键什么都不做**，不会进入蓄力。
- 选中态是**粘**的：一旦有棋子被选中，只有右键能取消它。左键点别的角色**不会改选**，
  但**照样开始给已选中的那枚蓄力**——瞄准时鼠标经常会压到别的角色，那时不让蓄力就没法瞄。
  想换角色必须先右键取消。
- **蓄力过程中把鼠标移出棋盘（`table_rect` 外）：蓄力暂停**——不涨也不退，鼠标回到盘内接着涨。
  这是给玩家一个"松手想一想"的余地，而不是把已经攒的力泄掉。
- **松开左键是唯一不可撤销点**：一旦松开，冲量施加、蓄力清零、发射边锁死，本回合不可重来。
- **零蓄力松手**：不施加冲量、不上锁，且**保留选中**，玩家可以直接重新蓄力。
- 整回合不发射：`MOTION` 不经过，直接进入 `TURN_END`。

**蓄力条 = 理想轨迹预测**（2026-10-10 新增）：

蓄力条不是一根长度条，而是**把球按真实物理推一遍算出来的折线**：从棋子出发沿瞄准方向前进，
撞到棋盘边就反射，一路画到球停下为止。它不预测与其他角色的碰撞（那是打出去才知道的事）。

- 条子的**末端就是球会停下的地方**（实测偏差 1~3%，来自逐帧积分的离散误差）。
- 长度是**平方**关系：`路程 = 蓄力值² / (2 × decel)`。半蓄力只走满蓄力的 1/4 距离。
- 撞墙会掉速度：反射后速度乘以有效弹性系数。

### 功能 3：移动碰撞（直到全场静止）【已实现】

**描述**：冲量施加后物理引擎接管，角色互相碰撞、撞墙反弹、受恒定滚动阻力减速，
直到**棋盘上所有角色**静止，本阶段结束。

**边界条件**：

- 静止判定是**棋盘级**的，不是角色级：一发球打出去后，被撞的敌方角色会继续运动并可能撞到第三枚，
  必须等到全场（含己方队友**和敌方角色**）静止才算本次行动结束。
- **静止判定必须去抖**：连续 N 个物理帧（默认 6 帧 ≈ 0.1 秒）所有角色的线速度与角速度
  都低于各自阈值，才判定为静止。碰撞瞬间速度可能恰好过零，单帧判定会误判。
- **角速度有独立阈值**：线速度接近 0 但原地打转，不算静止。
- **必须有超时兜底**：卡在边缘、反复微弹的角色可能长时间无法满足静止条件，超时后强制结束本阶段，
  并输出一条包含触发角色及其速度的警告日志（该日志本身是物理参数的排查线索）。
- 己方其他角色被撞动是合法且预期的行为：可以用队友当弹板。
- **棋盘四壁无摩擦**：这是为了让"入射角 = 反射角"成立，蓄力条才能如实预测轨迹。
  角色之间保留摩擦，所以球与球碰撞照样传递自转。详见 [全局约束](../00-overview/constraints.md)。

### 功能 4：碰撞结算与事件链【部分实现】

> 这是**环节 2 内部的插入点**：撞击敌方时插入血量交换。
> **数值链路已通**（行动角色撞到敌方就双向扣血、溢出给归属方；类型克制暂时屏蔽），
> **碰撞冻结也已实现**（冻结 → 播动画 → 解冻 → 结算双向伤害，见 [DESIGN.md](DESIGN.md)），
> **伤害落地时的屏幕抖动也已接通**（三档，见 [屏幕抖动](../50-presentation/screen-shake.md)）。
> 仍**未实现**的是：事件队列、表现时间线（伤害数字等）。

**描述**：碰撞不是"等回合末一起算"，而是**在碰撞发生的那一刻**就进入结算：

```
碰撞发生 → 物理冻结 → 生成事件 → 串行结算 → 表现 → 表现排空 → 解冻物理 → 运动继续
```

**边界条件**：

- **只有"行动角色 × 敌方"的碰撞才结算**（2026-10-10 决定）：
  本回合发射出去的那一枚撞到**敌方**才执行血量交换。
  **撞自己人不结算**（没有误伤），**被撞飞的角色再撞到别人也不结算**。
  所以一次发射的伤害来源只有"行动角色**直接**撞到的那些敌方"。
- **并非每次碰撞都冻结**。碰撞分两类：普通碰撞（只反弹）不冻结、不入队；
  有效果碰撞（伤害、技能触发）才冻结并入队。判定是一次**纯查询**（"这次碰撞会触发什么"），
  由规则层回答，不由棋子自己判断。
- **碰撞伤害是双向的**：碰撞双方都受伤，且即时结算，不等回合末。
- **溢出伤害**：一次伤害先扣角色的剩余血量（下限 0），**扣不完的部分结算到该角色归属方的血量池**。
  这是事件链的第二层，由队列串行展开。**角色不会死亡**——血量归零后仍留在棋盘上。
- **同帧多碰撞有确定先后**：一发球在一帧内同时撞到多枚角色时，按**全序键**排序后串行结算。
  全序键的首字段由内容层提供（当前为角色所对应卡片的序号），核心不认识"卡片"这个概念。
- **表现与结算同源**：伤害数字、爆炸、"−8" 白字这类表现只读事件数据，不回查规则。
- **具体数值本期不定义**：只确定结算时机、方向与链路，数值留到数值设计阶段，
  实现时以可调导出参数占位。
- **物理冻结必须精确**：冻结期间位置不得漂移、速度不得丢失，解冻后轨迹必须连续。
  该语义已实测确认，见 [冻结与暂停策略](../40-physics/freeze-and-pause.md)。

> ⚠️ **连锁反应不再造成伤害**：一发球把敌方撞飞、它再撞到第三枚——第三枚**只被推动，不掉血**。
> 同理，用队友当弹板也不再能"隔山打牛"。这是 2026-10-10 的刻意决定，
> 但它把"用队友当弹板""引发连锁"从**战术伤害手段**降级成了纯粹的**位移手段**。
> 如果以后觉得可惜，唯一的扩展点就是上面那条资格判定。

### 功能 5：控制域（ZOC）围攻结算【已实现】

> 这就是**环节 3**。

**描述**：全场静止后，从**本回合发射的那枚棋子**的控制域出发，挑**一个**敌方目标结算伤害。
它是**对玩家的奖励**——单向伤害，玩家只赚不赔。

**选目标的规则（2026-10-10 确定）**：

1. 先看"本回合发射的那枚棋子"的 ZOC 范围里有没有敌方。
2. 范围内有被本方 **≥2 个**控制域同时罩住的敌方 → 挑**罩得最多的那个**。这就是**围攻**。
3. 没有围攻 → 挑**离发射棋子最近的**那个（仍然由发射棋子的 ZOC 出发）。
4. **每回合只结算这一个目标。**

**边界条件**：

- **控制域是什么**（2026-10-12 明确）：以棋子为圆心、半径 `zoc_radius` 的圆。
  **没有碰撞体积**（不是物理体、不进碰撞检测），**只在 ZOC 步骤里检测一次**。
  判定是"这个圆与目标的 **`CollisionShape2D`** 交叠"——**不是**"目标中心落在圆内"，
  所以目标的形状半径要算进来：`距离 ≤ zoc_radius + 目标的形状半径`。
- **伤害是单向的**：只有目标受伤，本方一概不掉血。
  **整个 ZOC 结算都是单向的**——本文档原先写的"未成围攻时双向交换"**已作废**（2026-10-10）。
- 判定基于**全场静止后的终局站位**，不是移动过程中的实时位置。
- 控制域覆盖关系是一个**纯查询**（"某角色被哪些本方角色罩住"），任何需要它的地方
  （结算、未来 AI 推演、UI 高亮）都实时计算，不缓存、不设状态，避免"忘记更新"。
- **"行动角色必须参与围攻"由选取方式本身保证**：选目标是从发射棋子的控制域出发的，
  不需要再单独判一条。
- **伤害数值本期不定义**：以可调导出参数占位。
- 控制域半径是可调导出参数（单位：像素），由用户在编辑器中调试确定。

### 功能 6：结束回合【已实现】

**描述**：玩家回合的**唯一出口**是一个显式的"结束回合"按钮。

**为什么必须是显式按钮**：卡片系统里存在 0 费卡，意味着"还能继续操作"这件事永远不为空，
系统无法用"没有可做的事了"来推断回合该结束；同时"本回合不发射"本身是一种战术。
两者叠加的结论是：回合结束**只能**由玩家主动声明。

**边界条件**：

- **按钮在 `PLAYER_TURN` 和 `MOTION` 期间都可点**；`TURN_START` / `TURN_END` / `ENEMY_TURN`
  期间变灰。
- **点击只记下意愿，不立刻切阶段**：真正的切换由 `PLAYER_TURN` 的完成条件在"全场静止"
  满足时执行。所以"任何时候都能点、但静止后才真的走"是自然成立的，不需要额外的等待态。
  棋子还在飞的时候点结束回合 → 等它停稳 + 去抖满了才进 `TURN_END`。
- 离开 `PLAYER_TURN` 时会**清掉选中态与蓄力**，避免"棋子停在蓄力态但已经进了敌方回合"
  这种悬挂状态。
- 未发射任何角色就结束回合，是合法流程，不产生任何补偿或惩罚。

### 功能 7：卡牌装载（占位）【未实现】

**描述**：卡牌可以装载到角色上，也可以由玩家直接使用。

**为什么现在不做**：卡牌机制（费用、手牌、牌库、装载规则）由 [卡片机制](../30-card/PRD.md)
独立设计，本模块只负责**留位置**。

**当前落点**：`scripts/game_flow.gd` 上的 `play_card()` / `load_card()` 两个空方法。
出牌是 `PLAYER_TURN` 枢纽上的**动作**（不切阶段），操作许可也由阶段机发放，
所以接口放在阶段机上最容易找到。

### 功能 8：敌方回合（bot）【已实现，第一版】

> 对应决策 29「一期要做 bot」。第一版是**"会还手"的对手，不是"聪明"的对手**（决策 38）。

**描述**：`ENEMY_TURN` 从占位（停 1 秒）变成**真阶段**，与 `PLAYER_TURN` 结构对称：

```
TURN_END ─(1s)→ ENEMY_TURN ─(bot 出手)→ MOTION ─(静止)→ ENEMY_TURN ─(收工 + 静止)→ TURN_START
```

**为什么对称**：规则本来就是对称的 —— `_actor` 机制不区分敌我，谁被发射谁就是行动角色；
ZOC、静止判定、碰撞冻结全都不知道"是谁在打"。所以 bot 不需要第二条代码路径，
它只是**另一个发号施令的人**。

**关键点**：

- **`MOTION` 返回"发起方自己的枢纽"**，不再写死回 `PLAYER_TURN` —— 靠 `_active_owner` 判定。
- **出手许可与玩家共用同一道门**（决策 11）：bot 出手前问 `can_enemy_launch()`，
  和玩家问的 `can_operate_pieces()` 是同一个 `launch_available` 边锁。
- **发射出口也共用**：bot 走 `TurnController.launch()` → `release_charge()` → `piece_launched`，
  和玩家松手走的是同一条路。所以规则层不需要知道是谁在发射。
- **收工也共用**：bot 决策完调 `request_end_turn()`，和玩家按按钮是同一个意愿位。
- **出手过程对玩家可见**：bot 会先选中那枚棋子（亮起描边），停顿 `think_sec` 秒再发射。
  否则玩家只看到一枚球莫名其妙飞出去。

**第一版的决策粒度**（先按"最简单策略"落地，细节全是可调导出参数）：

| 决策 | 怎么定 | 旋钮 |
| --- | --- | --- |
| **打谁** | **对方血量最低的那一枚**。血量归零的**薄弱点**（决策 25）自然排在最前 —— 打它就是直接啃对方的血池，不用再单写一条 | — |
| **用哪枚** | **离目标最远的那一枚**（还在飞的不算）。与"打谁"合起来就是一句话：**从最远处打最弱的** | — |
| **蓄多少力** | **极限**（直接满）。伤害与速度无关（决策 24），但位移有关：撞飞距离 = 射程 − 已走距离，满蓄力给出最夸张的位移 | — |
| 准不准 | 瞄准加一点随机抖动，给难度留个旋钮 | `aim_jitter_deg` |
| 想多久 | 出手前停顿，让玩家看懂 | `think_sec` |

**明确不做（留给后续迭代）**：轨迹预测（现在瞄直线，不预测撞墙反射）、搜索、
评分函数、出牌。

## 用户场景

### 场景 1：一个完整的玩家回合

**入口**：Godot 编辑器运行 `sences/main.tscn`。
**操作流程**：

1. 棋盘右侧的 `LifeCycle` 标签显示当前阶段；开局从 `TURN_START` 起，停留 1 秒后进入 `PLAYER_TURN`。
2. 玩家点选任意一枚本方角色 → 角色描边变绿，瞄准线跟随鼠标。
3. 玩家按住左键 → 蓄力条（轨迹预测折线）随蓄力值变长。
4. 玩家松开左键 → 角色沿瞄准方向飞出，蓄力条清零，进入 `MOTION`，发射边锁死。
5. 全场静止（去抖确认）→ 回到 `PLAYER_TURN`。此时发射边仍锁着，点任何本方角色都选不中。
6. 玩家点"结束回合" → 阶段机走 `TURN_END` → `ENEMY_TURN` → `TURN_START`，
   各停留 1 秒 → 回到 `PLAYER_TURN`，发射边重新打开。

> 步骤 4 与 5 之间，**将来**会插入"撞到敌方角色 → 冻结 → 血量交换 → 表现 → 解冻"（功能 4）。

### 场景 2：本回合不发射

1. 玩家不点选任何角色，直接点"结束回合"按钮。
2. 阶段机跳过 `MOTION`，直接进入 `TURN_END`。
3. 棋盘上没有任何角色因此获得补偿或受到惩罚。

### 场景 3：选中后反悔

1. 玩家右键 → 选中态清除，描边褪去，瞄准线消失。
2. 玩家可以重新点选任意一枚本方角色。

### 场景 4：一次碰撞触发的完整事件链【未实现】

**触发条件**：该次碰撞被规则层判定为"有效果碰撞"。

1. 物理在碰撞回调中被冻结（位置零漂移、速度原样保留）。
2. 生成碰撞事件 → 结算规则产出两个伤害事件（双向）。
3. 事件队列按全序键排序后串行处理：先扣敌方血量，再扣本方血量。
4. 若伤害超过该角色剩余血量 → 产出溢出事件 → 超出部分结算到它归属方的血量池。
   （角色血量下限为 0，不会死亡、不会退场。）
5. 表现层消费这些事件，依次播出"−8 白字 + 爆炸"。
6. 表现排空后解冻物理，运动以冻结前的速度继续。

## 边界条件

| 场景 | 处理方式 |
| --- | --- |
| 左键在棋盘矩形外按下（未选中时） | 什么都不做 |
| 未选中角色就按住左键 | 不蓄力 |
| 已选中角色，按住左键 | 开始蓄力，**不论鼠标压在哪**（包括别的角色身上） |
| 已选中角色，左键点另一枚角色 | 不改选；照样给已选中的那枚蓄力 |
| 蓄力过程中鼠标移出棋盘 | 蓄力**暂停**（不涨不退），回到盘内继续 |
| 零蓄力时松手 | 不发射、不上锁、保留选中，可以重新蓄力 |
| 全场长时间无法静止 | 超时强制结束 `MOTION`，并输出警告日志 |
| 一发球把己方队友撞动 | 合法行为；队友的控制域参与围攻判定 |
| 敌方回合期间玩家点击鼠标 | 角色不接受输入（由阶段机发放操作许可，角色不自行判断） |
| 已发射过角色后本回合再次点击角色 | 不可选中（由发射边锁拦截） |
| 棋盘还在动时点"结束回合" | 记下意愿，等全场静止后才进 `TURN_END` |
| 同一物理帧内发生多次有效果碰撞【未实现】 | 按全序键排序后串行结算；排序键相同时以入队序号兜底，保证全序 |
| 某角色的伤害导致归属方血量归零 | 对局结束，该方失败（胜负的表现属其他模块） |
| 发射一枚角色后它自己没有移动 | 仍视为已发射，发射边锁死；`MOTION` 因全场早已静止而立即结束 |

## 非功能需求

- **性能**：静止判定每物理帧遍历全部角色（单场 ≤ 14 枚物理实体），**遍历中不得分配新容器**。
- **手感**：静止判定的去抖窗口 ≤ 0.1 秒；物理冻结与解冻不得造成可见的位置跳变或速度损失。
- **运行环境**：Godot 4.7 + `gl_compatibility` 渲染后端；2D 物理。详见 [全局约束](../00-overview/constraints.md)。
- **离线自包含**：全部实现与验证仅依赖本地项目目录。
- **可测试性**：规则必须能在 `--headless` 下用 `--fixed-fps 60` 回放验证，不依赖人工点击。
  阶段机、静止判定、发射边锁已有对应的 headless 探针。

## 验收标准

### 已实现部分

| 核心功能 | 验收标准 |
| --- | --- |
| 功能 1：阶段图 | 运行主场景 → `LifeCycle` 标签能观察到阶段按图推进；单帧内不出现两次推进；`TURN_START`/`TURN_END`/`ENEMY_TURN` 各停留约 1 秒 |
| 功能 1：发射边锁 | 发射一枚角色后再点其他本方角色 → 选不中；结束回合转一圈回来 → 又能选中 |
| 功能 2：两次按键 | 第一次点选只高亮不蓄力；第二次按住才开始蓄力；右键取消选中 |
| 功能 2：粘性选中 | 选中后点另一枚角色 → 选中态不转移，且不产生位移 |
| 功能 2：蓄力暂停 | 蓄力中把鼠标移出棋盘 → 蓄力值停住不涨；移回盘内 → 从冻结值继续涨，不重置 |
| 功能 2：蓄力条即轨迹 | 蓄力条末端与球实际停下的位置一致（偏差 ≤ 5%）；条子会撞墙反弹 |
| 功能 2：不发射 | 不选任何角色直接点"结束回合" → 跳过 `MOTION`，无任何角色位移 |
| 功能 3：全场静止 | 发射后撞动第二、第三枚角色 → 阶段机等到**所有**角色（含 Mob）停稳后才推进 |
| 功能 3：去抖 | 角色碰撞的瞬间（速度过零）不触发阶段推进 |
| 功能 3：超时兜底 | 人为制造无法静止的场景 → 超时后强制推进，且控制台出现含角色与速度的警告 |
| 功能 3：四壁无摩擦 | 斜射撞墙 → 角色自转不增加，实测反射角 = 入射角 |
| 功能 6：结束回合是唯一出口 | 停留在 `PLAYER_TURN` 静置任意时长 → 阶段机不自行离开，只有点按钮才进入 `TURN_END` |
| 功能 6：移动中点头不进 | 棋子还在飞时点结束回合 → 阶段机停在 `PLAYER_TURN`，停稳后才进 `TURN_END` |
| 功能 5：围攻成立 | 两枚我方控制域同时罩住一个敌方 → 两枚的 atk **之和**扣在它身上（实测 20） |
| 功能 5：单向 | 上述站位 → 只有目标掉血，**我方两枚一概不掉血** |
| 功能 5：罩得最多者优先 | 一个被 2 枚罩住、另一个更近但只被 1 枚罩住 → 打**被 2 枚罩住的那个** |
| 功能 5：无围攻时挑最近的 | 控制域内有敌方但无人被 ≥2 枚罩住 → 挑离发射棋子最近的，伤害 = 罩住它的那几枚之和（只有行动角色时即 10） |
| 功能 5：无行动角色不结算 | 本回合没发射 → 直接返回，谁都不掉血（行动角色是 ZOC 的入口） |
| 功能 5：触发点 | 发射后走完 `MOTION` 回到 `PLAYER_TURN` → 阶段机自动结算一次（实测 m1 掉 20） |
| 功能 5：薄弱点全额转移 | 目标已是薄弱点 → 血量不动，伤害全额转给它的归属方 |
| 功能 5：终局站位 | 结算依据是**静止后的站位**：实测全力一撞把目标弹出 44px，停在 76px 外（ZOC 只有 60）→ 不结算。这是物理结果，不是缺陷 |

| 26 | **归属方血量** | 每方 **99 点**（初定 30，2026-10-10 上调），归零即该方失败、对局结束 | 2026-10-10 |
| 27 | **召唤物** | 角色能力产生的**实体棋子**，**可被摧毁**（与角色相反），**无属性**，默认生成在执行角色的左边。数量受**每方「召唤物 + 角色」合计上限 7** 约束（角色占 3，故召唤物最多 4 个），超出时最早的召唤物自动销毁（FIFO，角色永不参与顶替） | 2026-10-10 |
| 28 | **角色类型** | 护卫（红）/ 斗士（绿）/ 施法者（蓝），克制三角 红>绿>蓝>红，克制方向伤害翻倍。**选中描边改为白色**，类型用贴图区分 | 2026-10-10 |
| 29 | **一期要做 bot** | `ENEMY_TURN` 从占位变成真阶段 | 2026-10-10 |
| 30 | **ZOC 结算** | **单向伤害**（只伤目标，本方一概不掉血）。**伤害 = 所有罩住目标的本方棋子的 `atk` 之和**（围攻人越多越疼）。选目标：从发射棋子的控制域出发，优先挑**被本方最多控制域同时罩住**的敌方（≥2 个即围攻），没有围攻则挑**离发射棋子最近的**。**每回合只结算一个目标** | 2026-10-10，补伤害来源 2026-10-12 |
| 31 | **碰撞伤害的资格** | **只有本回合发射的那一枚（行动角色）撞到敌方**才执行血量交换。撞自己人不结算（无误伤）；被撞飞的角色再撞到别人也不结算（无连锁伤害） | 2026-10-10 |
| 32 | **召唤物是"简化的棋子"** | 可被发射（占用每回合的发射机会）、**有控制域**、和角色在规则上一视同仁。它弱是因为"数值低 + 没有技能"，不是因为规则上给它设限 | 2026-10-12 |
| 33 | **设计原则：少给棋子类加约束** | 平衡问题优先用**数值 / 技能 / 机制**去调，**不要**在"棋子"这个类上堆特例分支。棋子类越简单，"加一个新玩法就要改核心"的风险越小 | 2026-10-12 |
| 34 | **OTK 是设计目标之一** | 一回合内击杀（One Turn Kill，参考炉石传说）是**这款游戏的魅力之一**。因此数值平衡**不得以"防止一回合击杀"为目标**——伤害应当能堆到致命。ZOC 取"覆盖者 atk 之和"正是为此：伤害要能叠加 | 2026-10-12 |
| 35 | **逻辑值与表现的关系** | **两者不必一致**，也不该为了对齐而互相迁就。所有数值默认就是**逻辑值**——规则层说了算、按规则时机生效；血条滚动、伤害飘字这类**动画扣血是纯表现**，可以滞后、可以后补，留到后期慢慢雕琢。这是回合制游戏，不需要"看见的数字 == 立刻的数字" | 2026-10-12 |
| 36 | **屏幕抖动** | 三档幅度：**轻微 / 严重 / 毁灭**，按需要调用；**伤害落地那一刻**触发（碰撞是结算时、ZOC 是第二拍），档位由伤害量决定。模式参考**炉石传说**：短促位移 + 一点旋转、衰减收敛，不是正弦振荡。**相机视野比窗口小一圈**，任一方向抖到最大都不露出画面外的空白 | 2026-10-12 |
| 37 | **敌方回合的结构** | `ENEMY_TURN` 从占位（停 1 秒）变成**真阶段**，与 `PLAYER_TURN` 对称：出手走 `MOTION`，收工后回 `TURN_START`。**`MOTION` 返回"发起方自己的枢纽"**（靠 `_active_owner` 判定），不再写死回 `PLAYER_TURN`。bot 的出手许可、发射出口、收工意愿**全部与玩家共用同一套**（决策 11） | 2026-10-13 |
| 38 | **bot 第一版的形态** | **"会还手"而不是"聪明"**：**不做轨迹预测、不做搜索、不做评分函数**。~~挑一对离得最近且够得着的「我方棋子 × 敌方目标」→ 瞄准 → 蓄"刚好够到 × 余量"的力~~ → **2026-10-13 修订，改成决策 39 那套**。原方案实测**总是同一枚棋子在动**、其余整局不动，谈不上策略感 | 2026-10-13，修订同日 |
| 39 | **bot 的选目标策略**（"最简单策略"） | 一句话：**目标 = 对方血量最低的棋子 → 射手 = 离它最远的那一枚 → 力度 = 极限（满蓄力）**。一次给出三件事：射手会换、目标会换（血线一变几何就变）、位移最夸张。**满蓄力一定够得着**（射程 600 px > 棋盘对角线 572 px），所以"极限力量"不需要额外的可达性判断 | 2026-10-13 |

## 剩余待定

- ZOC 结算的**具体伤害数值**：留到数值设计阶段。注意它是单向的，和碰撞的"双方各打 atk"不是同一套数值。
- 控制域半径的**具体像素值**：由用户在编辑器中调试手感后确定。
- ~~死亡角色是否从棋盘移除、何时移除（影响 `MOTION` 的碰撞体集合与静止判定的遍历范围）：属角色模块，但会影响本模块。~~
  **已定（决策 23）：不存在死亡，角色永不退场**，这条待定随之消失。
- ~~角色血量归零后**还能不能参与攻击/围攻**：属角色模块，会影响环节 3 的围攻判定。~~
  **已定（决策 25）：仍然全功能可用**——可被选中、可发射、控制域照常参与围攻。
  代价是它在碰撞中受到的伤害**全额转移给归属方**。
- **一次碰撞是否只结算一次**：连锁碰撞（A 撞 B、B 再撞 C）会结算多次吗？影响数值强度。
- **bot 决策机制的具体形态**：几期要做的第一条 AI。规则式还是评分式？
  决策粒度（选哪个角色 / 瞄哪里 / 蓄多少力）？见 [角色机制 PRD](../20-character/PRD.md)。
- 卡牌装载落在 `PLAYER_TURN` 的哪个时机（随时可装载？还是限定在某些子状态？）：
  等卡片模块设计推进后再定。
