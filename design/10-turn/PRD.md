# 回合机制 产品需求文档

> 模块：`10-turn` ｜ 状态：编写中
> 创建：2026-09-30 ｜ 最近修订：2026-10-04
> 原始来源：`ravenspec/changes/turn-lifecycle/PRD.md`（2026-09-30，已迁移到本文件并修订）
> 技术方案见 [DESIGN.md](DESIGN.md)

## 需求概述

把《弹棋·三国》的对局升级为**由回合阶段驱动的桌面战棋**：一个回合沿阶段图推进，
玩家在 `ACTION` 枢纽上反复做三件事——出牌、发射（每回合仅一次）、结束回合——
其中发射会走完"选中 → 蓄力 → 激发 → 移动碰撞 → 静止后结算"整条链路。

本模块要交付的不只是"流程能跑通"，而是一套**能容纳状态、结算与表现**的生命周期底座：
结算与表现同源于事件，物理在需要时可以被精确冻结并原样恢复，
同帧发生的多件事有确定的先后。这样角色池、技能池、卡片池日后扩展时，**不需要改动脊梁**。

## 核心功能

### 功能 1：回合阶段图

**描述**：回合生命周期建模为一张有向图。每个阶段只回答四个问题——进入时做什么、
什么时候算完成、退出时做什么、完成后去哪。推进由"完成条件"轮询驱动（每物理帧检查一次，
**至多推进一条边**），而不是信号链或协程。

**拓扑**：

```
TURN_START ─→ ACTION ─┬─ 出牌（自环，可任意次，0 费卡也走这里）────→ ACTION
                      ├─ 发射（每回合仅一次）→ SELECT → CHARGE → MOTION
                      │                                   → HIT_SETTLE → ZOC_SETTLE → ACTION
                      └─ EndTurn ─────────────────────────→ TURN_END → ENEMY_TURN
                                                                        │
                      TURN_START ←──────────────────────────────────────┘
```

**阶段表**：

| # | 阶段 | 中文名 | 本期状态 | 完成条件 |
| --- | --- | --- | --- | --- |
| 1 | `TURN_START` | 回合开始 | pass | 恒真 |
| 2 | `ACTION` | 行动枢纽 | 实现 | 出现"发射"或"结束回合"事件，**且**结算与表现均已排空 |
| 3 | `SELECT` | 选中角色 | 实现 | 左键按下并选中一枚本方角色；或取消选中 |
| 4 | `CHARGE` | 蓄力激发 | 实现 | 左键松开 |
| 5 | `MOTION` | 移动碰撞（直到静止） | 实现 | 全场静止（去抖确认）**且**结算与表现均已排空；超时兜底 |
| 6 | `HIT_SETTLE` | 攻击结算收口 | 实现 | 结算与表现均已排空 |
| 7 | `ZOC_SETTLE` | 控制域围攻结算 | 实现 | 结算与表现均已排空 |
| 8 | `TURN_END` | 回合结束 | pass | 恒真 |
| 9 | `ENEMY_TURN` | 敌方回合 | pass | 恒真 |

**关键边界**：

- **为什么是图而不是固定序列**：`ACTION` 有三条出边、`MOTION` 有一条回到 `ACTION` 的回边。
  用"固定序列"表达这两件事必须引入特例分支，而特例分支就是结构性缺陷的温床。
  图结构下，每个阶段只声明"我完成后去哪"，不声明特殊分支。
- **每物理帧至多推进一条边**（用 `if` 而非 `while` 驱动）。代价是连续穿过多个 pass 阶段
  需要数个物理帧（约 0.1 秒量级），肉眼不可见；收益是彻底排除帧内级联。
- **pass 阶段不是"空实现"**，而是"完成条件恒真的阶段"：照样经历 enter/exit 并发阶段变更信号，
  未来填充内容时不需要改动阶段机本身。
- **出牌不是阶段**：它必须能与选中/蓄力交替进行，因此是 `ACTION` 阶段内随时可用的**动作**。
  出牌产生的事件在 `ACTION` 内被结算与表现，**不引起阶段切换**。
- **`HIT_SETTLE` 的定位已重新定义**：原设计中它是"发起攻击/释放技能"的占位阶段；
  现在碰撞结算在 `MOTION` 内就被冻结式地即时处理，`HIT_SETTLE` 承接的是
  **全场静止后的一次性收口**（死亡判定、溢出血量落地、技能条件复核）。
  若编辑器实测证明收口逻辑可以并入 `ZOC_SETTLE`，则该阶段退回 pass——这是运行期观察结论，不是当前的设计承诺。
- **发射边的锁**：`ACTION` 的发射出边在每次发射后关闭，直到下一个 `TURN_START` 重新打开。
  这是一个**边上的开关**，不是"剩余次数"计数器——结构上不存在"某条路径忘了扣次数"的可能。

### 功能 2：发射（每回合一次，任意本方角色，可放弃）

**描述**：发射是本作的核心机制，类比台球：一个回合只有一次机会，玩家**自选**任意一枚
本方角色弹出。

1. **点选**（`ACTION` → `SELECT`）：在棋盘内点击一枚本方角色 → 进入选中态（视觉高亮）并显示瞄准线。
2. **蓄力**（`SELECT` → `CHARGE`）：按住左键 → 蓄力值按固定速率增长，蓄力条随蓄力值伸长。
3. **激发**（`CHARGE` → `MOTION`）：松开左键 → 沿"角色 → 瞄准点"方向施加与蓄力值成正比的冲量。
4. **放弃**：玩家可以不发射任何角色，直接点"结束回合"。这是**合法且必要的战术选择**
   （例如保持站位、等待 ZOC 成形、避免把队友撞散）。

**边界条件**：

- 正常情况：点选 → 按住 → 松开，三段连续完成，进入 `MOTION`。
- 发射前，本方**任意**角色均可被选中；发射后，本方所有角色本回合均不可再被选中。
- 未选中角色时按住左键：不进入 `CHARGE`，不蓄力。
- 选中后改选：点击另一枚本方角色 → 选中态转移，阶段保持 `SELECT`。
- 选中后取消：点击棋盘内空白处或按 Esc → 回到 `ACTION`，清除选中态与瞄准线。
- **松开左键是唯一不可撤销点**：一旦松开，冲量施加、蓄力清零、发射边锁死，本回合不可重来。
- 整回合不发射：`SELECT` / `CHARGE` / `MOTION` / `HIT_SETTLE` / `ZOC_SETTLE` 全部不经过，直接进入 `TURN_END`。

### 功能 3：移动碰撞（直到全场静止）

**描述**：冲量施加后物理引擎接管，角色互相碰撞、撞墙反弹、受恒定滚动阻力减速，
直到**棋盘上所有角色**静止，本阶段结束。

**边界条件**：

- 静止判定是**棋盘级**的，不是角色级：一发球打出去后，被撞的敌方角色会继续运动并可能撞到第三枚，
  必须等到全场（含己方队友）静止才算本次行动结束。
- **静止判定必须去抖**：连续 N 个物理帧（约 0.1 秒）所有角色的线速度与角速度都低于各自阈值，
  才判定为静止。碰撞瞬间速度可能恰好过零，单帧判定会误判。
- **角速度有独立阈值**：线速度接近 0 但原地打转，不算静止。
- **必须有超时兜底**：卡在边缘、反复微弹的角色可能长时间无法满足静止条件，超时后强制结束本阶段，
  并输出一条包含触发角色及其速度的警告日志（该日志本身是物理参数的排查线索）。
- 己方其他角色被撞动是合法且预期的行为：可以用队友当弹板。

### 功能 4：碰撞结算与事件链

**描述**：碰撞不是"等回合末一起算"，而是**在碰撞发生的那一刻**就进入结算：

```
碰撞发生 → 物理冻结 → 生成事件 → 串行结算 → 表现 → 表现排空 → 解冻物理 → 运动继续
```

**边界条件**：

- **并非每次碰撞都冻结**。碰撞分两类：普通碰撞（只反弹）不冻结、不入队；
  有效果碰撞（伤害、技能触发）才冻结并入队。判定是一次**纯查询**（"这次碰撞会触发什么"），
  由规则层回答，不由棋子自己判断。
- **碰撞伤害是双向的**：碰撞双方都受伤，且即时结算，不等回合末。
- **溢出伤害**：角色受到伤害后若血量降为负，**超出该角色总血量的部分累积并结算到玩家血量上**。
  这是事件链的第二层，由队列串行展开（详见 [DESIGN.md](DESIGN.md#事件链)）。
- **同帧多碰撞有确定先后**：一发球在一帧内同时撞到多枚角色时，按**全序键**排序后串行结算。
  全序键的首字段由内容层提供（当前为角色所对应卡片的序号），核心不认识"卡片"这个概念。
- **表现与结算同源**：伤害数字、爆炸、"−8" 白字这类表现只读事件数据，不回查规则。
- **具体数值本期不定义**：只确定结算时机、方向与链路，数值留到数值设计阶段，
  实现时以可调导出参数占位。
- **物理冻结必须精确**：冻结期间位置不得漂移、速度不得丢失，解冻后轨迹必须连续。
  该语义已实测确认，见 [冻结与暂停策略](../40-physics/freeze-and-pause.md)。

### 功能 5：控制域（ZOC）围攻结算

**描述**：全场静止后，在 `ZOC_SETTLE` 阶段做一次**本方全体控制域检测**：若某敌方角色 X
同时落在行动角色的控制域与至少一个其他己方角色的控制域内，则判定为**围攻**，
所有罩住 X 的本方角色一起对 X 发起攻击，形成本回合的第二次伤害结算。

**边界条件**：

- 判定基于**全场静止后的终局站位**，不是移动过程中的实时位置。
- 控制域覆盖关系是一个**纯查询**（"某角色被哪些本方角色罩住"），任何需要它的地方
  （结算、未来 AI 推演、UI 高亮）都实时计算，不缓存、不设状态，避免"忘记更新"。
- 未形成围攻（只有 1 个本方控制域覆盖 X）时，X 与该覆盖方之间发生**普通伤害交换**（双向结算）。
- **围攻的必要条件是行动角色必须参与**：行动角色不在"覆盖 X 的集合"里就不构成围攻。
- 围攻成立（≥2 个本方控制域同时覆盖 X）时，**伤害是单向的**：只有被围的 X 受伤，围攻方不掉血。
- **伤害数值本期不定义**：以可调导出参数占位。
- 控制域半径是可调导出参数（单位：像素），由用户在编辑器中调试确定。

### 功能 6：结束回合

**描述**：玩家回合的**唯一出口**是一个显式的"结束回合"按钮。

**为什么必须是显式按钮**：卡片系统里存在 0 费卡，意味着"还能继续操作"这件事永远不为空，
系统无法用"没有可做的事了"来推断回合该结束；同时"本回合不发射"本身是一种战术。
两者叠加的结论是：回合结束**只能**由玩家主动声明。

**边界条件**：

- 点击后：清除选中态与瞄准线 →（若结算或表现尚未排空，先等排空）→ 进入 `TURN_END`。
- 在 `ACTION` 或 `SELECT` 阶段均可点击；`CHARGE` 阶段按住左键期间按钮不响应（松开左键才是不可撤销点）。
- 在 `MOTION` / `HIT_SETTLE` / `ZOC_SETTLE` / `TURN_END` / `ENEMY_TURN` 阶段按钮不响应。
- 未发射任何角色就结束回合，是合法流程，不产生任何补偿或惩罚（补偿与否属于卡片/数值模块的事）。

## 用户场景

### 场景 1：一个完整的玩家回合

**入口**：Godot 编辑器运行 `sences/main.tscn`。
**触发条件**：游戏开始，处于玩家回合的 `ACTION` 阶段。
**操作流程**：

1. 玩家点选任意一枚本方角色 → 角色高亮，瞄准线跟随鼠标，阶段推进到 `SELECT`。
2. 玩家按住左键 → 蓄力条增长，瞄准线按蓄力比例缩短，阶段推进到 `CHARGE`。
3. 玩家松开左键 → 角色沿瞄准方向飞出，蓄力条清零，进入 `MOTION`，发射边锁死。
4. 角色撞上敌方角色 → **物理冻结**，双方各自受到碰撞伤害（即时结算），
   角色表面跳出伤害表现，随后解冻继续运动。
5. 若伤害造成溢出 → 溢出部分结算到玩家血量，表现层同时给出提示。
6. 连锁碰撞结束后全场静止（去抖确认）→ 进入 `HIT_SETTLE` 收口 → 进入 `ZOC_SETTLE`。
7. 若某敌方角色同时被行动角色与另一名己方角色罩住 → 判定围攻，单向结算。
8. 回到 `ACTION`。此时发射边已锁死，玩家仍可出牌；若无牌可出或不想出，点"结束回合"。
9. 阶段机走完 `TURN_END` → `ENEMY_TURN`（本期 pass）→ 回到 `TURN_START`。

### 场景 2：本回合不发射

**入口**：`ACTION` 阶段。
**触发条件**：玩家判断当前站位下发射不划算（如队友 ZOC 位置刚好）。
**操作流程**：

1. 玩家不点选任何角色，直接点"结束回合"按钮。
2. 阶段机跳过 `SELECT` / `CHARGE` / `MOTION` / `HIT_SETTLE` / `ZOC_SETTLE`，直接进入 `TURN_END`。
3. 棋盘上没有任何角色因此获得补偿或受到惩罚。

### 场景 3：选中后反悔

**入口**：同场景 1 的步骤 1 之后。
**触发条件**：已选中一枚角色，且尚未按住左键。
**操作流程**：

1. 玩家点击棋盘内空白处（或按 Esc）→ 选中态清除，瞄准线消失，回到 `ACTION`。
2. 玩家可以重新点选任意一枚本方角色，包括原来看中的另一枚。

### 场景 4：一次碰撞触发的完整事件链

**入口**：`MOTION` 阶段，一枚高速角色撞上敌方角色。
**触发条件**：该次碰撞被规则层判定为"有效果碰撞"。
**操作流程**：

1. 物理在碰撞回调中被冻结（位置零漂移、速度原样保留）。
2. 生成碰撞事件 → 结算规则产出两个伤害事件（双向）。
3. 事件队列按全序键排序后串行处理：先扣敌方血量，再扣本方血量。
4. 若某方血量降为负 → 产出溢出事件 → 结算到玩家血量。
5. 表现层消费这些事件，依次播出"−8 白字 + 爆炸"。
6. 表现排空后解冻物理，运动以冻结前的速度继续。

## 边界条件

| 场景 | 处理方式 |
| --- | --- |
| 左键在棋盘矩形外按下 | 不进入 `CHARGE`，不蓄力 |
| 未选中角色就按住左键 | 不进入 `CHARGE`，不蓄力 |
| 蓄力过程中鼠标移出棋盘 | 保持上一次的瞄准方向继续蓄力，不中断 |
| 全场长时间无法静止 | 超时强制结束 `MOTION`，并输出警告日志 |
| 一发球把己方队友撞动 | 合法行为；队友的控制域参与围攻判定 |
| 敌方回合 / 结算阶段玩家点击鼠标 | 角色不接受输入（由阶段机发放操作许可，角色不自行判断） |
| 已发射过角色后本回合再次点击角色 | 不可选中（由发射边锁拦截） |
| 玩家点"结束回合"时表现尚未播完 | 先等表现与结算排空，再进入 `TURN_END`（不打断已有表现） |
| 同一物理帧内发生多次有效果碰撞 | 按全序键排序后串行结算；排序键相同时以入队序号兜底，保证全序 |
| 某角色的伤害导致玩家血量归零 | 产出对局结束事件（具体判定与表现属角色/卡片模块，本期只保证事件能产生） |
| 发射一枚角色后它自己没有移动 | 仍视为已发射，发射边锁死；`MOTION` 因全场早已静止而立即结束 |

## 非功能需求

- **性能**：静止判定每物理帧遍历全部角色（单场 ≤ 10 枚），**遍历中不得分配新容器**。
- **手感**：静止判定的去抖窗口 ≤ 0.1 秒；物理冻结与解冻不得造成可见的位置跳变或速度损失。
- **运行环境**：Godot 4.7 + `gl_compatibility` 渲染后端；2D 物理。详见 [全局约束](../00-overview/constraints.md)。
- **离线自包含**：全部实现与验证仅依赖本地项目目录。
- **可测试性**：事件是纯数据、可序列化；表现时间线可在无渲染环境下加速跑完。
  规则必须能在 `--headless` 下回放验证，不依赖人工点击。

## 验收标准

| 核心功能 | 验收标准 |
| --- | --- |
| 功能 1：阶段图 | 运行主场景 → 控制台能观察到阶段按图推进；pass 阶段在数个物理帧内自动穿过；单帧内不出现两次推进 |
| 功能 1：ACTION 自环 | 出一张牌 → 结算与表现完成后，阶段机**仍停留在 `ACTION`**，不推进到 `SELECT` |
| 功能 1：发射边锁 | 发射一枚角色并回到 `ACTION` 后再点其他本方角色 → 不进入 `SELECT`；点"结束回合" → 进入 `TURN_END` |
| 功能 2：任意本方角色可选 | 发射前依次点选多枚本方角色 → 每次都能进入选中态并显示瞄准线 |
| 功能 2：取消与改选 | 选中后点空白处或按 Esc → 高亮与瞄准线消失；点击另一枚 → 选中态转移 |
| 功能 2：不发射 | 不选任何角色直接点"结束回合" → 跳过全部发射阶段，直接进入 `TURN_END`，无任何角色位移 |
| 功能 3：全场静止 | 发射后撞动第二、第三枚角色 → 阶段机等到**所有**角色停稳后才进入下一阶段 |
| 功能 3：去抖 | 角色碰撞的瞬间（速度过零）不触发阶段推进 |
| 功能 3：超时兜底 | 人为制造无法静止的场景 → 超时后强制推进，且控制台出现含角色与速度的警告 |
| 功能 4：冻结精确性 | 碰撞冻结期间逐帧采样位置 → 数值完全不变；速度值不变；解冻后轨迹与冻结前连续 |
| 功能 4：普通碰撞不冻结 | 让角色撞墙弹开 → 不产生冻结、不产生事件、运动不间断 |
| 功能 4：双向伤害 | 构造一次有效果碰撞 → 碰撞双方各自掉血 |
| 功能 4：溢出结算 | 构造"伤害超过角色总血量"的碰撞 → 该角色血量归零，超出部分从玩家血量扣除 |
| 功能 4：同帧定序 | 构造一帧内同时撞到两枚角色的场景 → 多次运行结算顺序一致，不随引擎回调顺序变化 |
| 功能 4：表现只读事件 | 断开支路后表现仍能正确播出数字与方向，不依赖回查规则状态 |
| 功能 5：围攻成立 | 构造"行动角色的控制域罩住敌方 X，且 X 还被另一枚己方角色罩住"的站位 → 判定围攻，两枚本方角色都攻击 X |
| 功能 5：围攻单向 | 上述站位 → 只有敌方 X 掉血，两枚围攻方均不掉血 |
| 功能 5：未成围攻 | 只有行动角色一人的控制域罩住 X → 不判定围攻，X 与该角色双向结算 |
| 功能 5：行动角色必须参与 | 罩住 X 的两枚己方角色都不是本回合发射的那一枚 → 不判定围攻 |
| 功能 5：终局站位 | 行动角色飞行途中曾覆盖 X 但停稳后不再覆盖 → 不判定围攻 |
| 功能 5：查询无缓存 | 移动任意己方角色改变覆盖关系后，重新查询立即返回新结果 |
| 功能 6：结束回合是唯一出口 | 停留在 `ACTION` 且可出牌、可发射的情况下，静置任意时长 → 阶段机不自行离开，只有点击按钮才进入 `TURN_END` |

## 非目标（本期不做）

- **卡片系统的机制**：打牌、费用结算、手牌管理、牌库——出牌在 `ACTION` 上留了位置，但机制另立模块
  （见 [卡片机制](../30-card/PRD.md)）。
- **卡牌赋予角色的挂载技能**：触发条件、持续、结束判定全部不做（见 [待设计](../90-todo/character-mounted-skills.md)）。
- **具体伤害数值与血条 UI**：本期只保证事件链路能产出正确的溢出结算结果，数值与表现形态由
  角色/数值模块定。
- **对局胜负判定**：玩家血量归零后的事件会产生，但"谁赢、怎么结算"不做。
- **敌方回合 AI**：`ENEMY_TURN` 保持 pass。
- **棋盘边缘类型区分**：荆棘边、深渊区域不实现，四边均为统一弹性边。

## 已确认的关键决策

| # | 事项 | 结论 | 日期 |
| --- | --- | --- | --- |
| 1 | 围攻是否必须行动角色参与 | **必须**。行动角色不在覆盖集合内则不构成围攻 | 2026-09-30 |
| 2 | 围攻的伤害方向 | **单向**：只有被围方受伤 | 2026-09-30 |

| 5 | 每回合发射次数 | **一次，是核心机制**（类比台球）。规则本身不可被突破；若未来需要突破，扩展点在"发射边锁"这一处，不需要引入计数器 | 2026-09-30，修订 2026-10-04 |
| 6 | 结束回合的触发方式 | **显式按钮，且是玩家回合的唯一出口**。修订自原表述"跳过本次发射的快捷方式"：0 费卡使"还能操作"永不为空，系统无法推断回合该结束 | 2026-09-30，修订 2026-10-04 |

## 剩余待定

- 围攻与普通伤害交换的**具体数值**：留到数值设计阶段。
- 控制域半径的**具体像素值**：由用户在编辑器中调试手感后确定。
- `HIT_SETTLE` 阶段是否真的需要独立存在：等 `MOTION` 内的即时结算链路跑通后，在编辑器里观察再定。
- 死亡角色是否从棋盘移除、何时移除（影响后续 `MOTION` 的碰撞体集合）：属角色模块，但会影响本模块的静止判定遍历范围。

## 回滚计划

- **改动性质**：纯新增脚本（`core/` 一组契约/工具/桥、`game_flow.gd`、`board.gd`、`turn_context.gd`）
  \+ `player.gd` 演进为 `piece.gd` + `main.tscn` 节点调整。无数据迁移、无存档格式变化、无外部依赖引入。
- **回滚方式**：`git revert` 对应的实现提交即可；演进前的 `player.gd` 完整版本在 git 历史 `94e546f`（修复pipline）中可随时取回。
- **部分回滚**：若"先点选、再蓄力"两段式手感在编辑器验证中不通过，可单独把 `SELECT` + `CHARGE`
  合并回单段式（按下即选中并蓄力），阶段图骨架与其余阶段不受影响。
  若事件队列过重，可先让 `HIT_SETTLE` / `ZOC_SETTLE` 退回 pass，仅保留 `MOTION` 内的碰撞结算。
- **回滚验证**：回滚后运行主场景，应回到"单球自由蓄力发射"的行为，且调试 Label 正常刷新。
