## 时间线是什么

时间线是一串**表现步骤**及其**具名标记**，它是表现的时钟。规则层不认识它，
它也不回查规则层——两者只通过事件通信。

它的两个职责：

1. **播**：把事件的视觉形态放出来（伤害数字、爆炸、位移、闪光）。
2. **报点**：在约定的时刻发出具名标记（`hit` / `end`），让关心时机的规则在那里结算。

## 契约

```gdscript
class_name Presenter extends RefCounted
signal finished
signal marker_reached(marker: StringName, event: GameEvent)

func play(_events: Array[GameEvent]) -> void: pass
func is_finished() -> bool: return true
```

## 三条硬规则

### 规则 1：表现只读事件，不回查规则

一次伤害要画出 `-8` 白字、方向、爆炸，所需的一切都必须已经在 `GameEvent.payload` 里。
表现层**不允许**去问"这一击是什么类型""这个角色还剩多少血"。

理由：同帧可能有多次伤害（双向交换、围攻三连），如果表现层自己去读血量当前值，
它就无法确定"这个数字对应哪一次伤害"，会出现数字与血量对不上的错位。

**推论**：事件的数据结构必须携带足够的表现信息（数值、来源、目标、方向、可选的属性/颜色）。
这是对 `GameEvent` 契约的硬要求，不是"以后再说"。

### 规则 2：可加速，不可跳过

时间线永远运行，事件一个不少、顺序不变。可变的只是**时间源**：

| 时间源 | 用途 |
| --- | --- |
| 真实 delta | 正常游玩 |
| ×N 倍速 | 玩家想快一点 |
| 立即完成 | `--headless` 回归测试、AI 推演、平衡跑批 |

**不提供"关闭表现"的开关。** 用户的不变量是"动效不可被关闭，所以挂在动效上的结算一定会发生"；
一旦允许跳过，事件就可能被漏触发。加速不破坏这个不变量，跳过会。

### 规则 3：没有表现的动作 = 零长时间线

每个动作都必须有一条时间线，哪怕长度为 0。表现资产缺失时，时间线**立即**发出全部标记并
进入 finished 状态——**结算照常发生**。

这条保证了"内容没做完"不会变成"规则不执行"。常见场景：新加一张卡片，效果写好了、
特效还没做，此时规则必须仍然正确运行。

## 结算挂在哪里：同一个机制，两个订阅点

这是"结算委托给动效"落地的方式，不需要两条代码路径：

```gdscript
# 不关心时机的规则（默认）：事件产生时立刻改状态
func apply(e, ctx) -> Array[GameEvent]:
	ctx.combatant(e.target_ids[0]).hp -= e.payload.amount
	return _overflow_events(e, ctx)

# 关心时机的规则：先不改状态，改为订阅时间线上的具名标记
func apply(e, ctx) -> Array[GameEvent]:
	present.marker_reached.connect(
		func(m, ev): if m == &"hit" and ev == e: _apply_damage(e, ctx),
		CONNECT_ONE_SHOT)
	return []
```

默认是前者。只有当某条规则真的需要"打到身上那一刻才掉血"时才用后者。
**不要**把"所有结算都挂到标记上"当作规范——那会让每一次结算都依赖表现资产存在。

## 与物理闸门的关系

时间线是物理闸门的**唯一持有者**：

```
结算入口申请 → 时间线 acquire → 播（期间物理冻结，位置零漂移、速度保留）
              → 时间线排空 → release → 运动以原速度继续
```

因此时间线的完成状态是阶段完成条件的一部分：`MOTION`（已实现）与将来引入的
结算收口阶段都必须等它排空才能推进。冻结的实测依据见
[物理冻结与暂停策略](../40-physics/freeze-and-pause.md)。
