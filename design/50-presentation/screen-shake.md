# 屏幕抖动

> 模块：`50-presentation` ｜ 状态：**已实现**（2026-10-12）｜ 最近修订：2026-10-12
> 代码：`scripts/shake_camera.gd`（相机）、`scripts/game_flow.gd` 的
> `_shake_for_damage()` 与 `is_presenting()`
>
> 本模块的另一半（表现时间线）**仍未实现**，见 [表现时间线与标记](timeline-and-markers.md)。

## 什么时候抖

**伤害落地的那一刻。** 这是抖动的唯一触发规则 —— 跟"打出去多少伤害"绑，不跟"谁撞谁"绑。

| 时机 | 抖不抖 | 为什么 |
| --- | --- | --- |
| 棋子撞上（冻结开始那一拍） | 不抖 | 这一拍是**挥剑**，还没打到 |
| 冻结结束、伤害结算 | **抖** | 这才是"打到了"的那一帧 |
| ZOC 结算（第二拍） | **抖** | 同上：围攻的伤害在这一拍落地 |
| 纯表现动作（zoc 检查、走动） | 不抖 | 没有伤害落地 |

落点是 `_end_freeze()`（碰撞结算）与 `_strike_zoc()`（ZOC 结算）——
两处都把**实际打出的伤害量**交给 `_shake_for_damage()`。

## 三档

`enum Level { MILD, SEVERE, DESTRUCTIVE }` —— 轻微 / 严重 / 毁灭。

档位由**伤害量**决定，阈值是相机上的导出参数（`severe_at` / `destructive_at`，默认 10 / 20），
在编辑器里调。想要固定档位就直接调 `shake(Level.SEVERE)` —— "按需要调用"的接口留着。

**规则层不认识"轻微/严重/毁灭"**：`game_flow.gd` 只播报"掉了多少血"，
"抖多狠"是表现层自己的判断。

叠加规则：**更猛的接管，更弱的不打断**。同一物理步撞两枚时，
`_end_freeze` 先取这一批里最重的一下，再交给相机。

## 抖动模式（参考炉石传说）

- **短促位移 + 一点点旋转**，衰减收敛；不是正弦振荡
  （正弦看起来像"晃"，随机取样才像"抖"）
- 衰减曲线用平方：前段猛、后段收得快（`amp = strength × t²`）
- 每帧重新采样随机值，所以没有周期、不会看腻
- 默认 3 / 8 / 16 px，时长 0.18 / 0.30 / 0.50 s，旋转上限 0.8°

抖动是**纯表现**：实测相机 offset ±12px 时棋子轨迹偏差 `0.000000000`
（见 [全局约束的实测表](../00-overview/constraints.md)）。所以这里用真随机不破坏确定性。

## 相机比窗口小一圈（抖动不露画面外空白）

抖的是相机，而相机的视野默认正好等于窗口 —— 抖起来就把画面边缘推出去，露出世界之外的空白。
所以**相机视野要比窗口小一圈**，给抖动留出余量。

`main.tscn` 里设 `reserve_px`（留白，像素），`zoom` 由它现算：

```
zoom = max( 720/(720 − 2r), 480/(480 − 2r) )     # 必须等比，取更严的那一轴
```

`r = 20` → `zoom = 1.0909` → 视野 660 × 440，横竖两边分别留 30 / 20 px。

**约束：`reserve_px` 必须 ≥ `destructive_strength`**，否则毁灭级抖动会露馅。
这条写成了 `_get_configuration_warnings()`，在编辑器里直接把警告摆出来。

> ⚠️ 别在编辑器里直接改 `Camera2D.zoom` —— 会被 `reserve_px` 算出来的值覆盖。要调画面大小就改 `reserve_px`。

## 抖动期间必须拦住阶段机与操作许可

相机一动，`get_global_mouse_position()` 就跟着偏（实测：相机 offset (12,-8) → 鼠标的世界坐标也偏 (12,-8)）。
所以抖动期间：

- 阶段机不推进（`_physics_process` 开头 `if is_presenting(): return`）
- **不发操作许可**（`can_operate_pieces()` 里也问同一句）

两件事由同一个 `is_presenting()` 回答（碰撞冻结 OR 正抖着），
"表现排空"因此只有一个定义，不会出现两处各拦一半。

## 实测（本机 Godot 4.7.2，headless 探针跑完整条链）

一次真实发射（Player1 撞 Mob，蓄力 300）：

| 测的事 | 结果 |
| --- | --- |
| 冻结时长 | **1.001 s** —— 恰好等于 `attack` 动画长度（12 帧 @ speed 12） |
| 冻结生效后的位置漂移 | **0.000000 px** |
| 解冻 | 双向掉血 70→60 / 70→60，紧接着开始抖（SEVERE，8 px，0.30 s） |
| 抖动期间阶段机 | **一次都没翻页** |
| 运动恢复 | 解冻后 0.021 s 棋子重新动起来 |
| ZOC 第二拍 | 也抖（t=4.568 s，Mob 60→50） |

## ⚠️ 这里是临时直连，将来要挪到标记上

`50-presentation` 的目标形态里，表现由**时间线的具名标记**驱动
（见 [时间线](timeline-and-markers.md)）：伤害落地 → 时间线发 `hit` 标记 → 抖。
现在时间线还不存在，所以 `_end_freeze` / `_strike_zoc` 直接调。

**判定该不该挪的标准**：如果需要"抖到一半就结算""加速回放""AI 推演时快进表现"，
直连就撑不住了；在那之前，直连更简单，也更不容易出"表现没播导致结算没发生"这类错。

  第一版先求"有"，精细化打磨时调 `mild/sec`、`severe/sec`、`destructive/sec` 三个时长。

- 伤害 → 档位的阈值（10 / 20）—— 现在对齐的是占位数值（`atk = 10`、`max_hp = 70`），
  数值设计定下来后要重调。
- 旋转要不要更大。炉石的观感里旋转占的比重不低，0.8° 是保守起点。
