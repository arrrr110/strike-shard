## 对局与回合

| 术语 | 英文 / 代码名 | 定义 |
| --- | --- | --- |
| 对局 | match | 从开局到分出胜负的完整过程。持有**归属方血量**等跨回合持久状态【未实现】 |
| 对局开始 | `MATCH_START` | 第一回合之前的正式时刻；技能/延迟效果可挂在这里【未实现】 |
| 回合 | turn | 一方的一次行动周期。玩家回合与敌方回合交替。**不引入「大轮」作为正式规则词** |
| 回合开始 / 结束 | `TURN_START(owner)` / `TURN_END(owner)` | 某一方回合的正式边界。每次 `TURN_END` 的**最后**（回合结束技能之后）双方各自把头像攻击力打到对方。当前阶段机有 `TURN_START` / `TURN_END`，但**没有 owner 参数化的公开事件、没有回合计数、敌方回合也没有独立 `TURN_END`**【部分未实现】 |
| 平局 | draw | 双方归属方在同一回合末**同时归零**。 |
| 可见性 | visibility | **棋盘上的操作、技能触发、头像攻击力、ZOC、角色状态双方都可见；只有各自手牌不可见**。 |
| 主动方 / 被动方 | active / passive | 本回合归属方 = **主动方**；对手 = **被动方**。技能激活/结算按这个顺序，不是按「谁先撞」 |
| 阶段 | phase | 回合内的一个步骤。阶段机在任一时刻只处于一个阶段，用 `UPPER_SNAKE` 命名。当前五个：`TURN_START` / `PLAYER_TURN` / `MOTION` / `TURN_END` / `ENEMY_TURN` |
| 阶段机 | game flow / `GameFlow` | 驱动阶段推进的脊梁（`scripts/game_flow.gd`）。每个物理帧轮询一次当前阶段的完成条件，**至多推进一个阶段** |
| 回合瞬时量 | — | 只存活一个回合的状态。当前只有两项，直接是 `GameFlow` 的成员：发射边锁、结束回合意愿。**没有独立的 `TurnContext` 类** |
| 动作 | action | `PLAYER_TURN` 枢纽上可做的一件事：装载卡牌、发射、结束回合。**动作不是阶段**，不引起阶段切换 |

> **`PLAYER_TURN` 而非 `ACTION`**：2026-10-10 统一。原文档叫 `ACTION`（行动枢纽），
> 与 `ENEMY_TURN` 不对称，改名为 `PLAYER_TURN`。

## 角色与棋盘

| 术语 | 英文 / 代码名 | 定义 |
| --- | --- | --- |
| 角色 | combatant / `Combatant` | **逻辑实体**：归属方、攻击、血量、控制域半径、卡片序号、挂载技能、失能状态。是结算的作用对象【未实现】 |
| 棋子 | piece | **物理实体**：角色在棋盘上的 `RigidBody2D` 表现，负责碰撞、摩擦、贴图倾斜。脚本是 `scripts/player.gd`。`mob.tscn` 也挂同一个脚本 |
| 归属方 | owner | 角色属于哪一方。`0` = 我方，`1` = 敌方。**持有血量池（99），归零即该方失败**【未实现】。扣减来源 = **对方归属方在 `TURN_END` 打过来的头像攻击力** |
| 失能 | disabled | **血量归零的角色**（旧称「薄弱点」）。不退场；**主动/被动技能全关、不提供 ZOC 覆盖**，但**仍可被碰撞、仍可作为 ZOC 目标**；仍可被选中、可发射。受到的**敌方**伤害给**攻击方归属方**充能，回合末双方各自结算。失能是**赛点**，不是胜负条件；只有归属方血量归零才分胜负。当前不可治疗/复活；未来有代价较大的**全局复活技能**【未实现】 |
| 归属方攻击力 | `owner_attack_power` | **owner 级、一次性、结算形式**：该归属方对**对方失能角色**造成的碰撞/ZOC/技能伤害累积到头像上；每次 `TURN_END` 的**最后**双方各自把攻击力打到**对方归属方**（各打各的，不抵消），随后清零。只是结算形式/表演，不是可消费资源。不是角色字段【未实现】 |
| 召唤物 | summon | 由角色能力产生的**实体棋子**（`RigidBody2D`）。与角色相反，**可被摧毁**（血量归零即从棋盘移除）。**无属性**，不参与类型克制。数量受「召唤物 + 角色」**每方合计 7 个**的总上限约束（角色占掉 3 个，故召唤物最多 4 个），超出时最早的召唤物自动销毁（FIFO）【未实现】 |
| 角色类型 | role type | 护卫 / 斗士 / 施法者。克制三角 **红 > 绿 > 蓝 > 红**，克制方向伤害翻倍。**2026-10-10 决定暂时屏蔽**——`role_type` 目前对伤害没有任何影响【克制未启用】 |
| 卡片序号 | `card_index` | 角色所对应卡片的序号，由**内容层**提供，核心只把它当作定序键的一个字段【未实现】 |
| 控制域 | ZOC (zone of control) | 角色周围半径 `zoc_radius` 的圆形范围。**纯查询**得到覆盖关系，不缓存、不存状态。**失能角色不作为覆盖者，但仍可作为 ZOC 目标**（可被围攻）【未实现】 |
| 围攻 | siege | ZOC 结算时，在发射棋子的控制域范围内**被本方最多个控制域同时罩住**的敌方角色。伤害单向，只伤它【未实现】 |
| 交换 | exchange | ~~未成围攻时，覆盖方与被覆盖方之间的双向伤害结算~~ **已作废（2026-10-10）：整个 ZOC 结算都是单向的** |
| 静止（棋盘级） | rest | 全场所有棋子的线速度与角速度**分别**低于各自阈值，且**持续 N 个物理帧**。由 `GameFlow._board_at_rest()` 判定，超时兜底 |
| 锁定（棋子级） | locked | 单枚棋子"还在动、暂不可被选中"。由 `player.gd` 自己维护，与上面的棋盘级静止是**两件事**：一个回答"这枚能不能点"，一个回答"回合能不能翻页" |
| 发射 | launch | 玩家消耗本回合唯一一次发射机会，把一枚本方角色弹出。是不可撤销点（松开左键那一下） |

## 结算与表现【整节未实现】

> 以下术语服务于环节 3（ZOC 围攻）与卡牌装载。设计论证保留在
> [回合机制技术方案](../10-turn/DESIGN.md) 第二部分，代码里一行都没有。

| 术语 | 英文 / 代码名 | 定义 |
| --- | --- | --- |
| 事件 | event / `GameEvent` | 机制里**唯一的真相载体**：发生了什么。纯数据，可序列化，可回放 |
| 结算 | settle / resolve | 事件引起的状态改变（扣血、局面翻转）。只能改状态，不能画东西 |
| 表现 | presentation | 结算的可视化（伤害数字、爆炸、位移、闪光）。只读事件，**不回查规则** |
| 时间线 | timeline | 一串表现步骤及其具名标记，是表现的时钟 |
| 标记 | marker | 时间线上的具名时间点（`hit` / `end`）。想要在动效某一刻结算的规则订阅标记；不关心的规则在事件产生时立刻结算 |
| 效果规则 | `EffectRule` | "某类事件发生时要做什么"的契约实现。输入一个事件，输出**一组新事件**，绝不直接调用另一条规则。**2026-11-02 起技能侧的具体实现叫 `Skill` / `SkillInstance`**（见下节）；`EffectRule` 作为一般概念保留 |
| 事件队列 | event queue | 串行排空事件的容器。链式效果靠"处理完一个再入队"展开，**不用递归** |
| 全序键 | order key | 给事件排序用的整数数组，字典序比较。保证任意两个事件都有确定先后 |
| 物理闸门 | `PhysicsGate` | 引用计数的物理冻结开关。唯一持有者是时间线 |
| 冻结 | freeze | 暂停物理积分而**不**暂停场景树：`PhysicsServer2D.set_active(false)` |
| 溢出伤害 | overflow | 仅指**造成失能的那一下**：扣掉角色剩余血量后多出来的部分，**丢弃**，不计入攻击力。失能之后的伤害不再叫溢出，叫「攻击方归属方头像攻击力」 |
| 归属方攻击力结算 | owner attack resolution | 失能期间受到的敌方伤害给攻击方归属方充能；每次 `TURN_END` 的**最后**双方各自把攻击力打到对方归属方，随后清零；归零即败；同时归零 = 平局 |

## 归属方血量 vs 角色血量【未实现】

- **角色血量**（`hp` / `max_hp`）：单个角色的耐久，**下限为 0**。
  **角色不会死亡**——血量归零后进入**失能**，仍留在棋盘上，
  可以继续被撞、被围攻、仍可被选中发射；但**技能全关、不提供 ZOC 覆盖**。
- **归属方血量**：（owner）一方的总耐久池，**99 点**，属于对局级状态，独立于角色。
  **归零即该方失败，对局结束**。
  扣减来源 = **对方归属方在 `TURN_END` 打过来的头像攻击力**：失能角色受到的敌方伤害
  给攻击方归属方充能；每 `TURN_END` 双方各自把攻击力打到对方。
- 两者是不同的状态，不得互相代替；界面上也是两个不同的显示区域。
- **失能是赛点，不是胜负条件**：只有归属方血量归零才分胜负；双方同一回合末同时归零 = 平局。
- 因此「角色被打空」的后果不是退场，而是**它失去全部主动/被动能力与控制域覆盖**；
  更关键的是，**敌人打它会给自己头像充能**，回合末反过来打我方。这是刻意的惩罚：
  保护低血角色的动机是「防止能力全关 + 阻止敌人积累头像攻击力」。
