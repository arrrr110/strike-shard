# 角色机制 产品需求文档

> 模块：`20-character` ｜ 状态：**骨架**（只有已定边界与待定项，未开展设计）
> 创建：2026-10-04
> 与回合机制的交界见 [回合机制 PRD](../10-turn/PRD.md)

## 已确定的边界

### 角色与棋子是两个东西

- **角色**（`Combatant`）：逻辑实体。归属方、攻击、血量、控制域半径、卡片序号、挂载技能。
  结算是作用在角色上的。
- **棋子**（`Piece`）：角色在棋盘上的物理实体（`RigidBody2D`）。负责碰撞、摩擦、贴图倾斜。

一一对应。分离的意义是：**结算不需要物理**（AI 推演、headless 测试都能跑）；
**物理不需要知道规则**（棋子只上报碰撞事实，不解释）。

### 血量模型

- 角色有 `hp` / `max_hp`。
- 一方另有一个**玩家血量**池，属于对局级状态（比回合长寿）。
- 角色受到的伤害超过其剩余血量时，**溢出的部分累积并结算到玩家血量**。
- 两者是不同的状态，界面上也是两个不同的显示区域。

### 属性契约（草案，来自回合机制的接口需求）

| 字段 | 含义 | 谁用 |
| --- | --- | --- |
| `id` | 角色唯一标识 | 事件寻址、定序兜底 |
| `owner_id` | 归属方（0 = 玩家，1 = 敌方） | 操作许可、围攻判定 |
| `card_index` | 对应卡片序号 | **仅用于定序**，由内容层提供 |
| `atk` / `hp` / `max_hp` | 战斗数值 | 结算 |
| `zoc_radius` | 控制域半径（像素） | 覆盖查询 |
| `mounted_skills` | 挂载技能 id 列表 | 见 [待设计](../90-todo/character-mounted-skills.md) |

## 待定（需要另行设计）

- 角色池：有哪些角色、各自的数值与专属效果。
- 死亡处理：血量归零后角色是否立刻从棋盘移除？何时移除？
  **这一条会影响回合机制**——它决定 `MOTION` 静止判定的遍历范围，以及运动中的角色消失是否合法。
- 伤害数值与公式：普通交换、围攻、围攻人数加成。
- 控制域半径的具体像素值：由用户在编辑器中试出手感。
- 角色的"朝向"是否有规则意义（目前贴图倾斜只是视觉表现）。
- 专属卡与角色的绑定关系。
