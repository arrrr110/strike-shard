## 归属方（Owner）

一局的双方各是一个**归属方**。归属方是比回合并寿的状态，持有血量池。

| 项 | 结论 |
| --- | --- |
| 数量 | 两个：我方（`owner_id = 0`）/ 敌方（`owner_id = 1`） |
| 血量池 | **99 点**（占位值，由用户在编辑器里试） |
| 头像攻击力 | **owner 级、一次性、结算形式**：该归属方对**对方失能角色**造成的碰撞/ZOC/技能伤害累积到头像上；每回合**结束阶段的最后**双方各自把攻击力打到对方归属方，随后清零。只是结算形式/表演，不是可消费资源 |
| 归零后果 | **对局结束，该方失败** |
| 一期的敌方 | **bot**。需要一个简单的决策机制（见"待定"） |
| 二三期的敌方 | 可以是其他玩家（联机）。**现在不设计**，但见下面的硬约束 |

**联机现在不做，但有一条现在就要守住的约束：确定性。**
二期要支持人类对手，意味着这套规则必须能在两端算出同样的结果——
固定物理步长、不依赖渲染帧、事件可序列化回放。本项目现在的
`--headless --fixed-fps 60` 探针做法正好是友好的，**不要引入只在客户端算的东西**
（随机数要显式播种、不要用真实时间做判定）。现在破坏它，二期要重写。

## 角色（上场角色）

| 项 | 结论 |
| --- | --- |
| 上场数量 | 每方 **3 个**（初定） |
| 能否被摧毁 | **不能**。角色永不退场 |
| 血量下限 | 0。到 0 后进入**失能**（2026-11-02 修订，旧称「薄弱点」） |
| 失能后的能力 | **主动/被动技能全部关闭；不提供 ZOC 覆盖**；但仍可作为 ZOC 目标（可被围攻）、可被选中、可发射、仍作为物理实体被撞。发射时仍按 `atk` 造成基础碰撞伤害——关的是技能，不是物理碰撞 |
| 失能后的伤害 | **计入攻击方归属方的头像攻击力**；当场不扣归属方血，每回合末双方归属方各自把攻击力打到对方（2026-11-02 起） |
| 失能后的治疗 | 当前**不可治疗、不可复活**；未来会有代价较大的**全局复活技能**（设计储备） |

**为什么要设失能这一档**：它把"角色被打空"从一个退场事件变成了一个**持续的战略负债**。
玩家不会因为角色被打空而少一个棋子，但会失去它的技能与控制域；更关键的是，
**敌人打它会给自己头像充能**，回合末反过来打我方归属方。保护低血角色的动机是
「防止能力全关 + 阻止敌人积累头像攻击力」。

**失能是赛点，不是胜负条件**：棋盘上的角色失能不等于输；只有归属方血量归零才分胜负。
失能给对手提供积累结算值的途径，所以它是「赛点」——逼近胜负，但不直接判负。

（2026-10-10 决定：角色不死亡的设定细化为「薄弱点」，当时定义为全功能可用、
伤害全额转给归属方。**2026-11-02 修订**：改为「失能」，技能与 ZOC 覆盖全关，
对它的伤害改为**计入攻击方归属方头像攻击力**，回合末双方各自结算；
旧定义保留在此处作为演变记录。）

## 血量模型

两套血量，不可互相代替，界面上也是两个不同的显示区域：

### 角色血量（`hp` / `max_hp`）

- 下限为 **0**，不会为负
- **归零即进入失能**，但角色不退场
- 失能期间受到的伤害不扣角色血量（已为 0），而是计入**攻击方归属方**的头像攻击力

### 归属方血量（owner HP）

- 一方的总耐久池，**99 点**
- 归零 → **对局结束，该方失败**
- **扣减来源 = 对方归属方在 `TURN_END` 把头像攻击力打到我方**（2026-11-02 定）：
  对方的攻击力来自「对方对我方失能角色造成的伤害」；每次 `TURN_END` 的**最后**
  （回合结束技能之后）双方各自结算，随后双方攻击力清零。旧规则里「即时溢出」不再存在。

### 伤害的去向

一次伤害 `D` 打到剩 `H` 点血的角色身上（**2026-11-02 最终口径：失能伤害转攻击力**）：

| 情形 | 角色承受 | 归属方当场承受 | 攻击方归属方头像攻击力 |
| --- | --- | --- | --- |
| `H > 0` 且 `D ≤ H` | `D`（血量降为 `H - D`） | 0 | 0 |
| `H > 0` 且 `D > H` | `H`（血量降为 0，进入失能） | 0 | 0（造成失能的那一下，超出部分**丢弃**） |
| `H == 0`（已失能） | 0 | 0 | `+D`（**计入攻击方归属方的头像**） |

> **2026-11-02 最终口径**：对失能角色的伤害不再进「受伤方延迟池」，而是变成
> **攻击方归属方的头像攻击力**。
> 1. **造成失能的那一下**，超出剩余血量的部分丢弃；只有角色已失能后受到的**敌方**伤害才计入。
> 2. 攻击力是 **owner 级、一次性**：同一归属方多个失能角色、多次攻击的伤害汇总到同一个头像。
> 3. **每次 `TURN_END` 的最后**（回合结束技能之后）：双方各自把头像攻击力打到
>    **对方归属方**（**各打各的，不抵消**），随后清零。
>    例：我方 10、敌方 4 → 敌方 -10、我方 -4；我方 10、敌方 0 → 敌方 -10、我方不变。
> 4. **归属方血量归零 → 该方失败，对局结束**；**双方同时归零 = 平局**。
> 5. 失能角色仍可被碰撞、被围攻；**不提供 ZOC 覆盖，但可以作为 ZOC 目标**。
>
> **实现提醒**：当前阶段图只有玩家回合的 `TURN_END`，敌方回合直接回 `TURN_START`；
> 要实现「每回合末」必须先补敌方回合结束钩子（见 [10-turn PRD](../10-turn/PRD.md) 的周期模型）。
> 攻击力是 owner 级状态，建议与 `owner_hp` 放在一起；`reset_match` 清零。

## 伤害公式

**伤害 = 攻击方 `atk`。碰撞速度不参与。**（2026-10-10 决定）

- **类型克制暂时屏蔽**，所以现在**没有倍率**：`伤害 = atk`。
  启用后才有"克制方向 ×2"。见上节。
- 召唤物无属性，永远不吃克制、也不触发克制

> ⚠️ **这条决定的连锁后果，必须说清楚**：蓄力只决定**射程与落点**，不决定伤害。
> 蓄力条的几何预测依然成立（末端仍是球停下的地方），但它**不再预测伤害**——
> 全力一撞和轻碰一下，只要撞到同一个角色，伤害完全一样。
> 蓄力的意义从"打多疼"退化成"打到谁、打几个"。
> 若以后觉得这个退化不可接受，改法是回到"atk 为基、速度调制"，见"待定"。

**碰撞伤害是双向的**：碰撞双方**各打出自己的 `atk`**，互相扣血。
不是"撞的一方打人、被撞的一方挨打"。（2026-10-10 用户确认。）

**只有 ZOC 结算是单向的**：围攻成立时只有被围方受伤，围攻方不掉血（见下）。
其余场合（碰撞）都是双向。

> 实现备忘：现在 `atk` 是 10、`max_hp` 是 70（全员统一占位值），
> 所以一次碰撞双方各掉 10 血。先前用 30/40 时一撞掉掉四分之三血，手感像"两边都在挨打"。

## 召唤物

| 项 | 结论 |
| --- | --- |
| 来源 | 角色的能力产生（属卡片/技能模块，本模块只定义它是什么） |
| 形态 | **实体棋子**（`RigidBody2D`），和角色一样参与物理与碰撞 |
| 能否被摧毁 | **能**。血量归零即从棋盘移除——这一点与角色相反 |
| 属性 | **无属性**，不参与类型克制 |
| 数量上限 | **「召唤物 + 角色」合计每方上限 7**。角色固定 3 个且不可摧毁，所以**召唤物最多同时存在 4 个**。再生成时**最早的那个召唤物自动销毁**（FIFO，角色永不参与顶替） |
| 生成位置 | 默认在**执行角色的左边**；**不得与现有棋子重叠**（元规则，需放置校验） |
| 归属 | 属于召唤它的角色所在的归属方 |

**召唤物一出现，就对回合机制提出两条硬要求**（见 [回合机制技术方案](../10-turn/DESIGN.md)）：

1. **棋子名单会在对局中变化。** 回合机制原先假设名单恒定（"角色永不退场"），
   现在不成立——静止判定必须在召唤物生成/被摧毁/被顶替后立刻看到新名单。
2. **不能在物理回调里直接释放刚体。** 摧毁一个正在参与碰撞的 `RigidBody2D` 必须延迟到物理步之后。

**FIFO 顶替还需要一张按归属方分组的登记表**：上限要求知道"哪个是最早的"，
所以每个 owner 要维护一份**有序**的召唤物清单。这张表和上面第 1 条是同一套数据结构
——一旦有它，静止判定的名单刷新也就有地方挂了。

**为什么把角色也算进上限**：7 是**棋盘上属于这一方的实体总数**，不是"召唤物配额"。
角色占掉 3 个固定名额且永不释放，所以实际留给召唤物的只有 **4** 个。
好处是"一方最多在场上堆多少东西"只有一个数字，不用把角色数和召唤物数各记一遍。
若以后上场角色数改了（例如改成 4 个），召唤物空间会**自动**变成 3 个，不需要另立规则。

> 边界情形：万一某方的角色数本身就达到 7，则召唤物没有空间、也没有可顶替的对象
> （角色不可销毁）。当前角色数固定 3，不会发生；如果以后角色数可配，这里要加一条拒绝规则。

> 性能影响：每方 ≤ 7、双方合计 **≤ 14 个物理实体**（原红线是"单场角色数 ≤ 10"）。
> 已按新规模更新 [全局约束](../00-overview/constraints.md)。

## 属性契约

| 字段 | 含义 | 谁用 |
| --- | --- | --- |
| `owner_id` | 归属方（`0` = 我方，`1` = 敌方） | 操作许可、围攻判定、伤害去向 |
| `atk` | 攻击力 | 伤害结算 |
| `hp` / `max_hp` | 角色血量，下限 0 | 结算、失能判定（`hp == 0`） |
| `kind` | 角色 / 召唤物 | 能否被摧毁、是否参与克制 |
| `type` | 护卫 / 斗士 / 施法者 / 无属性 | 克制判定 |
| `zoc_radius` | 控制域半径（像素） | 覆盖查询；**失能角色不作为覆盖者，但可作为 ZOC 目标** |
| `card_index` | 对应卡片序号 | **仅用于定序**，由内容层提供 |
| `mounted_skills` | 挂载技能 id 列表 | 见 [技能系统](../35-skill/PRD.md) |
| `disabled` | `hp == 0` 的派生状态（建议只读） | 技能/ ZOC/ 治疗查询；失能期间受到的伤害给攻击方归属方充能；不要手写反向同步 |

> **归属方级新增字段**：`owner_attack_power`（或同义命名）——一次性头像攻击力，
> 索引 = `owner_id`。它来自该归属方对**对方失能角色**造成的伤害；`TURN_END` 双方各自
> 把攻击力打到对方后清零。它不是角色字段，建议与 `owner_hp` 放在一起。

> **`controllable` 已退役（2026-10-10 落地）。** 它原先同时承担两件事——
> "这枚是谁的"（我方 = `true`，敌方 = `false`）和"我能不能操作它"。
> 现在归属由 `owner_id` 回答，能不能操作由阶段机按阶段发放
> （[回合机制技术方案](../10-turn/DESIGN.md) 决策 11）。
> 不拆开的话，二期接入人类对手时"敌方是另一个玩家"会无处安放。
>
> **2026-10-12 补充**：归属判定从棋子**移到了选择层**（`TurnController._pick` 按
> `GameFlow.active_owner_id()` 过滤）。原先 `is_selectable()` 写死 `owner_id == 0`，
> 会让敌方棋子永远选不中——规则对称但入口只有玩家能用。改完之后 bot 只要让
> `ENEMY_TURN` 期间 `active_owner_id()` 返回 `1`，敌方棋子就自动可选，不用再改棋子。

## 已确认（2026-11-02 失能相关）

- **失能 = `hp == 0`**：主动/被动技能全关、**不提供 ZOC 覆盖但可被围攻**、
  仍可被选中/发射、不可治疗/不可复活（复活未来作为代价较大的全局技能单独设计）。
- **失能伤害转为头像攻击力**：造成失能的那一下超出部分丢弃；之后**敌方**对失能角色造成的
  碰撞/ZOC/技能伤害计入**攻击方归属方**的头像攻击力；每 `TURN_END` 的**最后**
  双方各自把攻击力打到对方归属方（各打各的，不抵消），随后清零；归零即败。
- **归属方结算放在回合结束阶段的最后**；**双方同时归零 = 平局**。
- **失能是赛点，不是胜负条件**；只有归属方血量归零才分胜负。
- **失能不能被 #1/#4 这类治疗/增益撤回**；未来的复活技能必须显式设计代价。

## 待定（需要另行设计）

- **攻击力来源口径**：当前按「敌方对已失能角色的所有碰撞/ZOC/技能伤害」计入；
  如果只希望碰撞计入，需要收窄。
- **友方伤害不计入**：当前只有敌方对失能角色的伤害才充能；友方误伤/自伤不计。
- **攻击力是否跨回合**：当前是一次性，`TURN_END` 结算后清零，不跨回合累积。
- **复活/攻击力**：攻击力已经在攻击方头像上，当前按「不因目标复活而回滚」；
  如果复活要清债，需要显式写。
- **敌方回合结束钩子**：当前阶段图只有玩家回合的 `TURN_END`，敌方回合直接回
  `TURN_START`；「每回合末」需要先补这个钩子。
- **失能后的技能状态**：计数器/待发标记是清空还是冻结？未来复活后是否恢复？
