# 视频 → 精灵图流水线

把一段 2D 角色视频（mp4）转换成**透明背景、锚点稳定、左右留白对称**的精灵图 PNG。

- **输入**：mp4。角色为主体，背景越干净越好（白底/纯色最佳）。
- **输出**：精灵图 PNG + GIF 动效预览 + 深色背景预览。
- **平台**：**仅 macOS**。依赖系统自带的 AVFoundation 与 Vision，不需要 ffmpeg、不需要下载模型、不联网。

> 这是 Gorest 那套「Agent 画图 + 代码洗图」里**洗图那一半**的本地实现。
> 区别是美术来源不是生图模型，而是你自己拍/生成好的视频——所以不依赖任何订阅环境。

---

## 快速开始

```bash
cd dodge_the_creeps_2d_assets/sprite_pipeline
./make_spritesheet.sh /path/to/hero.mp4 --start 3.0 --frames 16
```

首次运行会自动做两件事：

1. 用 `swiftc` 把 `swift/` 下两个小工具编译到 `.bin/`
2. 在 `.venv/` 里安装 Pillow / numpy

输出默认放在视频同目录：

```
hero_spritesheet_16f.png          # 精灵图
hero_spritesheet_16f.gif          # GIF 预览
hero_spritesheet_16f_preview.png  # 深色背景预览
```

## 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--start <秒>` | `0` | 抽帧起点。**避开镜头推拉/变焦的段落**，否则角色会逐帧变大 |
| `--end <秒>` | 视频结尾 | 抽帧终点 |
| `--frames <N>` | `16` | 等步长抽多少帧 |
| `--cell <WxH>` | `256x192` | 单元格尺寸 |
| `--cols <N>` | `4` | 列数，行数自动 = `ceil(frames/cols)` |
| `--margin <px>` | `8` | 安全边距 |
| `--fps <N>` | `10` | GIF 预览帧率 |
| `--out <path>` | 视频旁 | 输出 PNG 路径 |
| `--work <dir>` | 临时目录 | 中间帧目录（默认保留，方便检查） |
| `--no-decontaminate` | — | 跳过白底去污染 |
| `--no-gif` / `--no-preview` | — | 不生成对应预览 |
| `--clean` | — | 成功后删除中间帧 |

## 流水线

```
mp4
 ├─[1] AVFoundation 抽帧（等步长）
 ├─[2] Vision 前景分割（白底 / 投影 / 水印一起处理）
 ├─[3] 白底去污染（只改半透明边缘的 RGB）
 ├─[4] 锚点计算与对称留白（躯干质心）
 └─[5] 预乘 alpha 缩放 → 拼图 → PNG / GIF
```

## 为什么这么做（都是踩过的坑）

### 1. 抽帧为什么用 AVFoundation 而不是 ffmpeg

macOS 自带，不依赖 Homebrew；而且 `requestedTimeToleranceBefore/After = .zero` 能精确取到指定时间点，不会因为关键帧对齐而取错帧。

### 2. 为什么用 Vision 而不是色键

白底角色最怕三样东西：**柔投影、边缘抗锯齿、角落水印**。色键会把投影留成灰斑、把浅色部位抠出洞；Vision 的前景分割把主体整体识别出来，这三样一起解决。而且是本地推理，不下模型。

### 3. 为什么锚点是躯干质心，不是包围盒中心

角色手持长矛时，包围盒被拉向一侧。按包围盒居中，身体会偏到格子左边，游戏里每帧都得算不同偏移。按**躯干质心**（包围盒上部 55% 的 alpha 质心）居中，偏移量是常数。

实测对比（张飞，跑步姿势）：

| 锚点候选 | 帧间标准差 |
| --- | --- |
| 脚部质心（底部 15%） | 14.5 px |
| 躯干质心（上部 55%） | **5.1 px** |
| 全图 alpha 质心 | 4.1 px |

脚在跑步时本来就在动，所以脚部锚点最不稳。全图质心被长矛拉偏。躯干质心是语义和稳定性之间最好的折中。

### 4. 为什么左右留白要对称

以平均锚点为中心，向左、向右各取相同的半宽 `M`（`M` = 所有帧里左右最大超伸的较大者）。

这样**长矛向右伸 x 像素，左边也空 x 像素**——锚点永远在格子水平中心，游戏里只需要一个固定偏移量。

### 5. 为什么统一全局缩放，不逐帧缩放

逐帧按包围盒缩放会让角色在动画里"呼吸"，还会把测量噪声放大成抖动。只允许一个 scale，保留原动作的位移和比例。

### 6. 为什么必须去白底污染

半透明边缘像素的 RGB 往往混了白背景。深色棋盘上，这些像素会变成一圈**白边**。

实测（张飞单帧）：

| 指标 | 修前 | 修后 |
| --- | --- | --- |
| 边缘平均 RGB | `[131, 119, 117]` | `[63, 48, 46]` |
| 边缘「接近白」比例 | 12.0% | **1.9%** |

去污染按 `C = A·F + (1-A)·白` 反解前景色 `F`，**只改 RGB，不动 alpha**。所以轮廓、几何、锚点全部不变。

### 7. 为什么预乘 alpha 再缩放

Pillow 直接缩放 RGBA 不预乘，透明边缘会掺进周围像素，产生白边/黑边。流程是：乘 alpha → 缩放 → 反预乘。

### 8. 为什么采样窗口要避开推近段

很多 AI 生成的视频前几秒带**镜头推近/变焦**，角色会逐渐变大。直接全片抽帧，8 帧播完角色会明显放大。

处理办法不是逐帧缩放归一（那会引入抖动），而是**把采样窗口挪到变化稳定的片段**（如 `--start 3.0`）。实测张飞从「440→489px，+11%」降到「464→489px，且无单调趋势」。

## 输出规格

- RGBA PNG，透明背景
- 每格尺寸 = `--cell`
- 锚点在格子**水平中心**
- 内容距格子边缘 ≥ `--margin`
- 垂直方向**底部对齐**（脚/地面是棋子的稳定接触点）
- 附带的 `_preview.png` 是深灰底，方便检查白边和边缘

## 在 Godot 里使用

1. 把 PNG 放进项目，Godot 自动导入为 `Texture2D`。
2. 这是**手绘风**，纹理过滤保持默认的 **Linear**；不要开 Nearest（Nearest 是给像素画的）。
3. 新建 `AnimatedSprite2D` → `SpriteFrames`，每帧用 `AtlasTexture` 切出对应格子（region = `x*cell_w, y*cell_h, cell_w, cell_h`）。
4. **锚点**在格子水平中心、底部留 `--margin`。把 `sprite.position` 或 `sprite_base_position` 调成身体/脚对准刚体原点。如果你是按「躯干质心」做偏移，所有帧共用一个值。
5. 播放帧率建议 **8~12 fps**。棋盘上 32~86px 的尺寸，再高也看不出来。

## 已知限制

- **仅 macOS**。Vision 和 AVFoundation 都是系统框架。
- **不是循环动画**。首尾帧不闭合，循环播放会跳。要循环得选一段真正的循环素材，或自己做首尾过渡。
- **逐帧分割可能有轻微闪烁**。在 32px 的棋子上基本不可见；如果将来用于卡面特写，再考虑时序稳定化或手工修边。
- **主体必须明确**。复杂背景、多主体、主体占比过小时，Vision 可能选错或失败。
- **mp4 不支持 alpha**。输入请用白底/纯色背景；已经是透明视频的话，直接拿帧进 `python/pack_spritesheet.py`，跳过分割。
- 对称留白假设**只有一个主要角色**。

## 故障排查

| 现象 | 原因 / 处理 |
| --- | --- |
| `需要 Xcode Command Line Tools` | 运行 `xcode-select --install` |
| `no foreground found` | 背景太复杂或主体太小；换一段背景更干净的视频 |
| Pillow 安装失败 | 检查网络；或手动 `python3 -m venv .venv && .venv/bin/pip install Pillow numpy` |
| 某帧触到安全边距 | 角色动作幅度超过格子；加大 `--cell` 或 `--margin` |
| 角色逐帧变大 | 采样窗口包含了推近段；用 `--start` 避开 |
| 边缘有白边 | 确认没有加 `--no-decontaminate`；再看 `_preview.png` 的深色底 |
| 锚点看起来偏 | 本工具按躯干质心居中；如果你的游戏要按脚锚定，自己在 Godot 里补偿 |

## 实测记录：张飞（2026-10-20）

源文件：`SS-TCG/zhangfei.mp4`，960×720，5.0545 秒，H.264。

```bash
./make_spritesheet.sh SS-TCG/zhangfei.mp4 --start 3.0 --frames 16 --cell 256x192 --cols 4
./make_spritesheet.sh SS-TCG/zhangfei.mp4 --start 3.0 --frames 8  --cell 256x192 --cols 4
```

| 项 | 结果 |
| --- | --- |
| 采样窗口 | 3.0 → 5.0545 秒 |
| 锚点 | 478.0 px（源图尺度） |
| 对称半宽 M | 404.0 px |
| 裁剪框 | x[66, 890) y[130, 636) = 824×506 |
| 缩放 | 0.2913 |
| 内容尺寸 | 240×147（256×192 格子） |
| 16 帧输出 | 1024×768（4×4） |
| 8 帧输出 | 1024×384（4×2） |
| 左右预留 | 各 128 px |
| 长矛最大右超伸 | 119 px |
| 内容高度 | 139~146 px（16 帧） |
| 边缘接近白 | 3.2% |
